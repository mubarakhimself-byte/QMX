## What works

Paradigm is a real contract: **pack-and-grant kit over the four application-layer products plus QMF**, not a sixth COMP, not screen-kit, not n8n/Hermes as a runtime, not a marketplace. Copilot is one shared platform capability; a pack may omit a profile; an instance may omit a panel.

- **Inherited table** binds parent AD-1..AD-31 read-only. Conflict examples (sixth COMP, json-render/MCP Apps as identity, nested grant union, app-use applying a change-request) are named as conflicts, not overrides. Trading-system completeness (parent AD-11/14/22/23/25) is inherit-do-not-re-elicit, which matches the CORE sitting. The single named parent amendment (AD-8 `app_instance_id` optional on authoring) is the right *form*.
- **AD-1 / AD-2** keep QMF as toolbox and QMA as host, not owner of every op. Bytes live in plugin tree + daemon install/instance rows. Execution owner is the COMP on the descriptor. Installing/enabling is not granting. Headless packs are first-class AD-3 steps. Widgets never own invoke. Broker/venue stays QMN. Closed QMA store classes stay closed.
- **AD-3** folds home/general into `profile=authoring` with no third `ProductSessionProfile`. App-use remains the weaker seat and must not apply. Pack/instance copilot is optional. `sess:` stays the engine run. Panel dispose does not cancel work (parent AD-17). Reconnect does not replay unacked intent (parent AD-29). Context transfer is `selected_refs` or `change_request` only. Nested invoke still does not union grants (parent AD-10).
- **AD-4** puts `caller_kind` on one envelope (`user` \| `agent` \| `workflow`). Many-to-many is Graph Template edges plus parent AD-10 modes — not a fifth composition mode. Workflow-to-workflow is nested Mission (`start` / `query-state` / `cancel` / `await`); live Task Graph merge is refused. Partial failure does not silently substitute instance/version/account.
- **AD-5** names the missing operator-log plane: daemon stdlib JSON-lines, listing axes including `healthy`, JobHandle in QMA AD-17 vocabulary, typed refusal, `correlation_id` join (never fp1), harness-authored telemetry, closed `failure_class`. Does not extend `qmn/FAILURES.md`. Logs are not evidence (parent AD-16).
- **AD-6** puts ordinary retry in the host and implementation repair on parent AD-29 change-request. Effect-class matrix is inherited (no blind `external-egress`). App-use may mint; authoring + operator apply. Alerts never authorize. HMR stays dead.
- **AD-7 / AD-8** keep weak-model operate on descriptors ∩ grants ∩ schemas ∩ typed refusals; skills/HTML/catalog cannot grant; json-render and MCP Apps stay unpinned presentation adapters; chrome remains GAP-0081 / GAP-0100.
- **Deferred table** is mostly the right park: GAP-0081/0100 chrome, presentation pins, third profile, CheckpointManifest, model roster, app-specific recipes, GAP-0058/0062 with “mini-apps must not assume a machine.”
- **Brownfield honesty:** fixtures at 34c148b are connect/amend, not e2e (DEC-0286). Daemon operator logger is absent and named as the connect. Envelope has no `caller_kind` today.

### High

#### H-1 — Named AD-8 amendment makes authoring `app_instance_id` optional without binding envelope `instance_id` or GrantRecord evaluation

**Where:** Inherited “Named parent amendment: AD-8 `app_instance_id`”; AD-3 Rule (“Main authoring may `selected_refs` other apps… nested invoke still does not union grants”); J-KIT-03; parent AD-8 durable field `app_instance_id`; parent AD-24 envelope `instance_id` required, “Ambiguous instance/config resolution refuses”; brownfield `ProductSession.app_instance_id: str` plus `_require_str("app_instance_id", …)` and `app_instance_id == context.instance_id` @ 34c148b (`product_session.py`); `InvocationEnvelope.instance_id: str` required; extra envelope fields refuse.

**Two conforming units**

- **Unit A — envelope-still-required epic.** Session `app_instance_id` MAY be absent iff `profile=authoring`. Every public call still carries a concrete `envelope.instance_id` that MUST match the GrantRecord’s `instance_id` for that hop. Authoring `granted_ops` may cite grants for more than one instance; each hop evaluates one GrantRecord; no union. `selected_refs` names the contribution; it does not mint grants. Absent/ambiguous instance refuses (parent AD-24).
- **Unit B — null-instance epic.** Reads the amendment literally. Authoring sessions and envelopes omit `instance_id`. Invoke uses “whatever is selected” or a synthetic home instance. Parent AD-24 uniqueness domain `(… instance_id …)` and mismatch refusals become optional. A third unit copies B’s grants onto the authoring session (the union AD-3 Prevents).

All three obey “no third profile,” “app-use still requires instance,” and “nested invoke does not union” as slogans. What diverges: whether parent AD-24 `instance_id` still binds, where authoring grants live, and whether J-KIT-03 is inspect-only or a real invoke path.

This sitting’s job is the home/main seat. The defect is uniqueness of the named amendment: it changes the session field and does not restate the envelope/grant law it must not weaken. Brownfield currently *requires* the string; the amendment is a real connect, not a comment.

**Action:** autofix. One closed clause under the named amendment (and AD-3/AD-4):

1. `product_session.app_instance_id` MAY be absent iff `profile=authoring` (home / nothing selected). `profile=app-use` remains required. No third profile.
2. Parent AD-24 is **not** amended: `InvocationEnvelope.instance_id` stays a required string on every public call. Ambiguous/missing instance still refuses.
3. When session `app_instance_id` is absent, `envelope.instance_id` MUST equal the GrantRecord `instance_id` for that hop; `grant_id` MUST be in that session’s `granted_ops`. `selected_refs` does not copy or union another session’s tools.
4. Brownfield: `_require_str("app_instance_id")` @ 34c148b is the baseline this amendment changes for the **session row only**.

#### H-2 — AD-1 lists `view:*` as a contribution point; parent AD-17/AD-2 forbid that until a named GAP-0081 `ui_view` increment

**Where:** local AD-1 Rule (“contribution points (ops, optional `view:*`, optional copilot profile as a **request**)”); parent AD-2 (“`view:*` is a wire DTO only (AD-17) — **not** a plugin contribution point and **not** a ContributionHit until a named GAP-0081 `ui_view` increment”); parent AD-17 (“Pack `view:*` is a wire DTO, not a plugin point”); companion `CONTRACTS.md` §1 (correctly “optional `view:*` DTOs (parent AD-17)”).

**Two conforming units**

- **Unit A — parent-law epic.** Pack `contributes` remains `{point, local_id}` for ops (and copilot profile as request). `view:*` stays a wire DTO. No ContributionHit for views. GAP-0081 still owns `ui_view`.
- **Unit B — contribution-point epic.** Reads AD-1 literally. Adds `view:*` as a plugin point / ContributionHit so a pack can “ship views.” That silently opens parent AD-2/AD-17 and can look like json-render/MCP Apps gaining a grant path (the thing local AD-8 Prevents).

Charitable intent: AD-1 meant “pack may request views as DTOs.” The spine writes them in the contribution-point list. Companion is already correct; the Rule is not.

**Action:** autofix. In AD-1: contribution points = ops + optional copilot profile as a **request**. Optional `view:*` remains a parent AD-17 wire DTO, not a plugin point, not a ContributionHit, not a json-render runtime id. Tag no GAP-0081 increment in this sitting.

#### H-3 — Host SDK numeric defaults this sitting owns are not closed: retry attempts and nested-Mission recursion budget

**Where:** AD-6 Rule (“Retry is host/SDK behaviour, on by default”; “A pack may declare tighter retry (fewer attempts) but MUST NOT declare looser”); AD-4 Rule (“Recursion budget on nested invoke remains (parent AD-10)”); parent AD-10 (“Bounded cycles of **invocation** require a recursion budget” — no number); parent AD-24 effect-class matrix and `call_depth` (no max); J-KIT-05 / J-KIT-06; `IMPLEMENTATION-SEQUENCE.md` steps 3–4; 09-18 rubric M-6 left the budget as a direction.

**Two conforming units (retry)**

- **Unit A — bounded host retry.** Host owns the AD-24 matrix. Default is a finite attempt cap for `none`/`read` (and idempotent replay for the other classes). Packs may only lower the cap. `external-egress` still must not blind-retry.
- **Unit B — unbounded “on by default.”** Host retries `read` until success or operator cancel. “Fewer attempts” is compared to infinity. Ordinary flake becomes a hot loop.

**Two conforming units (nest)**

- **Unit A — refuse-closed budget.** Default max `call_depth` is 0 unless the operator raises a single host configurable. Nested Mission at depth 1 is an explicit raise.
- **Unit B — generous or unlimited depth.** Nested Mission ships with max 8 (or no max). Template DAG remains acyclic; invocation cycles run until stack/timeout.

This sitting’s job is default host retry and workflow-to-workflow. Parent AD-24 already closed *whether* a class may retry; it did not close *how many times*. Parent AD-10 already required a budget; it did not close the default. “Remains” and “fewer attempts” do not prevent two SDKs.

**Action:** autofix.

1. Retry: host default attempt cap is a closed integer (recommend **3** total attempts for `none`/`read`; other classes follow parent AD-24 identity/CAS/receipt law and do not get a second physical effect). Packs may set `max_attempts` ∈ `[1, host_default]` only. Timeouts/backoff may ride that cap; they must not add attempts. No infinite retry.
2. Nested Mission: recursion budget is one host configurable, default **refuse-closed at 0** (no nested invoke) unless the operator raises it. `call_depth` on the envelope is the counter; exceeding the budget is a typed refusal, not a splice. Include-subgraph at authoring remains a new versioned template (AD-6 DAG still binds).

# QMX - Epic Breakdown

## Overview

This document is the epic and story breakdown for the **UI host plus backend-delta** increment (FEAT-0064..FEAT-0071): absorb the 2026-09-23 UI spine and the 2026-09-24 backend-delta spine so an operator can open a differentiated-shell Svelte client, pair a browser to a host-supervised daemon, chat on Home without an instance, stage artifacts, publish a draft into the local authoring pack, mount pack views with a host-minted ActionContext, and cancel work from the originating session.

## Requirements Inventory

### Functional Requirements

**A. Differentiated-shell chrome (DEC-0469 / DEC-0470 / DEC-0474 / DEC-0482; FEAT-0064)**

- FR-UI-01: The product UI is a client of `qma-wire` (CT-40) talking to `qma-daemon`. Chrome never becomes a COMP, a scheduler, or a grant store. No `COMP-UI`. No sixth application. No new CT. (DEC-0505; constitution L7/L31)
- FR-UI-02: A persistent narrow platform rail shows destinations **above** a divider and opened-app icons **below**. With zero opened apps the destinations above the divider are Home, Copilot, Library, Authoring. Settings is chrome, not a fifth product destination. (DEC-0470; SCN-0034)
- FR-UI-03: Home is work / attention / resume. Copilot is the conversation workspace. Shared `SessionList` / `ConversationPane` components do not merge the destinations. Home/Authoring use profile `authoring`; in-app copilot uses `app-use`. No third `ProductSessionProfile`. (DEC-0470; SCN-0034)
- FR-UI-04: Authoring is independently reachable with zero apps open. Library is a platform destination overlaying ArtifactHit / KnowledgeHit / ContributionHit without collapsing kinds. Headless packs (no `view:*`, no `copilot_profile`) remain first-class with no navigation pane. (DEC-0471; DEC-0476; SCN-0034)
- FR-UI-05: Unique issuers live at `apps/qmx-ui/src/lib/host/`: `dispatchInvoke`, `dispatchChat` → `send_message`, `dispatchCancel` → `cancel_job`. Widgets never import the wire client. There is no `caller_kind=widget`. (DEC-0474; DEC-0484; DEC-0489)
- FR-UI-06: Home may chat with `app_instance_id` absent and must not mint a synthetic instance. Home/Authoring may not invoke until exactly one `selected_refs` kind `instance_id` is present; envelope `instance_id` remains required. (DEC-0484; DEC-0463)
- FR-UI-07: Close / unmount is `wire.detach`. It does not cancel JobHandles and does not stop the daemon. (DEC-0479)
- FR-UI-08: One `producer_id` per chrome tab. Product-session `command_id` is unique per `psess:` across tabs. Invocation `idempotency_key` applies only to `dispatchInvoke`. Sharing a live `producer_id` across tabs is forbidden. (DEC-0490)
- FR-UI-09: Native QMX Svelte pane is the default presentation lane. json-render and MCP Apps stay optional unpinned adapters. This increment does not mint a `ui_view` contribution point. (DEC-0472; DEC-0481)
- FR-UI-10: Home attention consumes parent AD-15 listing axes, kit diagnosis, and parent AD-25 fencing as **observation**. It does not authorize live, hot-swap, or treat a dashboard filter as a command target. Trading ticket chrome stays GAP-0113. (DEC-0480; GAP-0100)
- FR-UI-11: Host stack seed is Svelte 5.57.1, SvelteKit 2.70.3 `@sveltejs/adapter-static` `ssr=false`, TypeScript 5.9, Vite 8.3.0, Tailwind CSS 4.3.3, shadcn-svelte 1.7.0 Rhea, bits-ui 2.19.3, `@xyflow/svelte` 1.6.6. Toolchain is Node.js `>=22.12.0 <23.0.0` and pnpm with `apps/qmx-ui/pnpm-lock.yaml`. SPA origin is never daemon port 8765. (DEC-0469)
- FR-UI-12: v1 is a browser client of an already-running daemon. The browser does not spawn Python. Tauri 2 is a later optional shell (GAP-0112). (DEC-0478; DEC-0485)
- FR-UI-13: New UI work lives on the `ui-integration` sibling stream. Combine with backend `integration` only for a tested deployment candidate. User-facing stories require Reticle `reticle_act_and_wait` / `reticle_assert` with `verified: "yes"`. (DEC-0482)
- FR-UI-14: Ordinary analytics charts use shadcn / LayerChart. Financial candlesticks use a dedicated host behind `WidgetFrame`. Provenance, units, timezone, and freshness are visible. Missing, empty, truncated, and denied stay distinct. (DEC-0483)
- FR-UI-15: Reconnect is a query (`initialize` same `producer_id`, snapshots, `wire.attach`, `JobHandle.reattach`, `list_mailbox`). It does not replay intent. Chrome states loading / empty / unavailable / failed / reconnecting / stale / unknown stay distinct. (DEC-0477; J-UI-06)
- FR-UI-16: UI/core capability mismatch (J-UI-13) keeps the shell usable; chat/invoke/cancel that need a missing method refuse with a typed incompatibility. Client-bit update (J-UI-14) does not rewrite daemon sqlite. (J-UI-13; J-UI-14)

**B. QMB host lifecycle and first operator (DEC-0494 / DEC-0503; FEAT-0065)**

- FR-UI-17: Privileged verbs are `qmb host start|status|stop|configure|rotate-control|recover-control` on a token-gated loopback **host-control** channel under `QMA_DAEMON_ROOT`, outside port 8765. QMB never writes daemon sqlite. (`pair` / `pair revoke` are FEAT-0066.) (DEC-0494; AM-10; AM-15)
- FR-UI-18: Product data root is Windows `%LOCALAPPDATA%\QMX\qma-daemon` (and the POSIX rows in HOST-LIFECYCLE.md). Inspect cwd-relative `qma-daemon-data` is not the product root. (DEC-0510 A14)
- FR-UI-19: `qmb host start` on an **empty** root (no `local_operator` row) mints `local_operator` and `host_control`. A root that already has `local_operator` but is missing `host_control` is not empty bootstrap and must not remint a principal. (DEC-0503; SCN-0028)
- FR-UI-20: Only `qmb host configure pairing-ttl` writes `registry:pairing.session_ttl`. CT-40 `variable.set` of that key refuses. Missing TTL refuses `/pair/start` and `/pair/confirm` issue. This increment mints no duration (GAP-0109). (DEC-0492; DEC-0510 A10)
- FR-UI-21: Running-daemon host-control verbs require the current token. Narrow exception: `stop` when the token file is missing or unreadable, allowed only for the OS owner of the root, so recover-control can run. Do not broaden that exception. (DEC-0494; SCN-0030)
- FR-UI-22: `rotate-control` presents the current token and remints the file; `local_operator` unchanged. `recover-control` runs on a **stopped** daemon by the OS owner without presenting the lost token; it is a one-shot daemon journal writer, does not bind 8765, preserves `local_operator` and journals, and remints no second principal. (DEC-0503; SCN-0030)
- FR-UI-23: The browser does not spawn Python. Until host verbs exist, UI Start local is setup copy. A provider `cred://` is not operator login. Broker allowlist is not widened. (DEC-0485; DEC-0503)

**C. Pairing admission (DEC-0485 / DEC-0491 / DEC-0492 / DEC-0493; FEAT-0066)**

- FR-UI-24: `pairing_proof` is the bearer. `pairing_record_id` is the journal identity. Journal stores `proof_fp1`, never the raw proof. HTTP uses `Authorization: Bearer pairing:<proof>` — never `pairing:<id>`. (DEC-0492)
- FR-UI-25: A remembered Origin never issues a new proof. Issuance is (1) `qmb host pair <code>` of **that** pending then `POST /pair/confirm`, or (2) authenticated `POST /pair/renew` with an unexpired unrevoked proof matching that Origin. Confirm-once count is 1. (DEC-0491; SCN-0028)
- FR-UI-26: Unauthenticated HTTP is allowed **only** for `POST /pair/start`, `POST /pair/confirm`, and CORS `OPTIONS` on the named daemon HTTP routes. OPTIONS never issues a proof, never upgrades WebSocket, never returns bytes. `POST /pair/renew` is authenticated. Hold Story 41.4’s unauthenticated-bind sentence for this carve-out (AM-01). (DEC-0493)
- FR-UI-27: WebSocket offers subprotocols `qmx.ct40.v1` and `qmx.pair.<proof>`. Cookies, `localStorage`, and IndexedDB are forbidden homes for the proof. `Set-Cookie` on `/pair/*` is a spec miss. (DEC-0485; DEC-0501)
- FR-UI-28: Browser home is memory plus `sessionStorage`. Same-tab reload may restore the proof. Closed tab is cold start: empty storage, `list_mailbox` restore, never auto-resend. Cloned tab copies storage: existing proof plus a new `producer_id` if the old one is live. `/pair/renew` is an explicit rotate, not the clone path. (DEC-0501)
- FR-UI-29: Authenticated CORS `Access-Control-Allow-Origin` is the exact paired static Origin (never `*`). Start/confirm may reflect the requesting Origin. Credentials omit. SPA origin ≠ daemon origin. (DEC-0493)
- FR-UI-30: `qmb host pair revoke --origin <origin>` is a `journal_seq` barrier at R: every pairing_session and pairing_pending for that Origin with `journal_seq` < R is revoked. Renew-then-revoke kills the new proof. Revoke-then-renew of the old proof refuses. `--session` revokes that `pairing_record_id` only. After R a new `/pair/start` is legal. (DEC-0492; SCN-0029)
- FR-UI-31: Browser-paired `AuthenticatedWireSession` carries `principal_class=operator` and `pairing_record_id`, and does not populate `credential_ref`. Machine clients still present `credential_ref`. Lost confirm body: proof unrecoverable; start a new pending. (AM-11; DEC-0493)
- FR-UI-32: `qmb host pair <code>` and `pair revoke --origin|--session` belong to this feature, not FEAT-0065 In. `initialize` advertises capability `pairing`. (DEC-0500)

**D. Mailbox session binding (DEC-0484 / DEC-0495; FEAT-0067)**

- FR-UI-33: Durable delivery stays Story 46.4 / FEAT-0045. This feature **amends** the Envelope field list with additive `product_session_ref` (QMA `_ref` law), **excluded from Envelope fp1**. It does not replace Story 46.4 and does not stand up a parallel conversation store. Hold Story 46.4’s Envelope field list for this field. (DEC-0495; AM-02; AM-14)
- FR-UI-34: Addable query `list_mailbox` is an Epic 41 / FEAT-0041 name (AM-08). When `product_session_ref` is present, `send_message` and `list_mailbox` admit only if the connection’s operator principal equals that session’s durable principal. Quant/machine rows with no product conversation omit the field. (DEC-0495)
- FR-UI-35: Pre-ack identity is wire pair `(producer_id, id)`. Same pair plus same payload hash returns the prior result. Same pair plus different hash refuses for **journal lifetime** (AM-12; mailbox sends only). Cold start never auto-resends. (SCN-0031)

- FR-UI-37: Missing `list_mailbox` capability is typed `query_unavailable`, not a successful empty mailbox. (J-UI-13)

**E. Artifact PUT and transfer (DEC-0488 / DEC-0497; FEAT-0068)**

- FR-UI-38: Initial possession is authenticated HTTP `PUT /artifacts/stage` on the daemon origin (`Content-Length` required, Bearer pairing proof). There is no JSON-RPC `stage_artifact` command. PUT is a byte channel, not invoke, not a BFF. (DEC-0488; AM-05)
- FR-UI-39: Missing `registry:artifact.stage_max_bytes` refuses the PUT. This increment mints no number (GAP-0110). Interrupted v1 PUT is refused and incomplete bytes are deleted; no partial fp1. (DEC-0497; SCN-0032)
- FR-UI-40: Completeness is daemon-recomputed fp1 plus byte count. Browser hash is not possession. (DEC-0497)
- FR-UI-41: `transfer_artifact` issues a ticket only when the source daemon origin is recorded reachable TLS the destination can dial. Default loopback is typed `source_unreachable`. Silent local fallback is refused. Daemon never dials in. (AM-06; SCN-0032)
- FR-UI-42: Destination authors `transfer_complete` after hash and byte-count verify. Only the ticket audience may `GET /artifacts/<fp1>` with the ticket header. Invoke on that placement refuses until the ticket is `complete`. (DEC-0497; SCN-0032)

**F. Editor drafts and first Run (DEC-0487 / DEC-0499; FEAT-0069)**

- FR-UI-44: Subsequent saves require durable id plus `expected_revision` equal to the current head fp1. Reload-head is addable query `get_editor_draft_head`. Stale CAS is typed conflict, not last-writer-wins. (AM-17)
- FR-UI-45: `publish_editor_draft` checks ownership, CAS, reruns validation against the immutable fp1, and writes the local authoring-pack contribution (unpublished roster item). QMA AD-22 RefinementProposal is not the graph editor store (AM-07). (DEC-0499; SCN-0033)
- FR-UI-46: First Run is publish into the **local authoring pack**, then parent AD-30 enable, then grant, then select that instance, then `dispatchInvoke`. Run on a mutable draft is typed `draft_not_runnable`. Distributable export is not the first enable. (DEC-0487; SCN-0033)

**G. PackUiRequest and ActionContext (DEC-0481 / DEC-0486 / DEC-0498; FEAT-0070)**

- FR-UI-47: Host ingests at most one `qmx.ui.pack_ui_request.v1` document at enable. It is a versioned request DTO, not a contribution point and not a grant. (DEC-0498)
- FR-UI-48: Optional `PluginManifest.copilot_profile` stays Epic 60 / Story 60.1. PackUiRequest references it and must not nest, replace, or forbid it. Do not hold Epic 60.1. (DEC-0481)
- FR-UI-49: Read-back is addable query `get_pack_ui_request` keyed by enabled `instance_id` + `availability_revision`. Record on the existing plugin-install / instance row; not a new sqlite name. (AM-16)
- FR-UI-50: Each mount receives an immutable host-minted `ActionContext`. Matching GrantRecords: zero → paint, invoke refuses; one → that record; two or more → typed `GRANT_AMBIGUOUS` (no first-wins). (DEC-0486)

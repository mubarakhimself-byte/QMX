### openai-cookbook/examples/partners/model_selection_guide/model_selection_guide.ipynb

- Core pattern: **model tiering / escalation ladder** — cheap-fast model for breadth + initial filtering, escalate to powerful model for depth/critique. Framework given as "start with simplest, upgrade when…" tables per task.
- Model-intro matrix: GPT-4o (realtime voice/vision), GPT-4.1 (1M-token text accuracy, no native reasoning), o3 (deep tool-using reasoning, high latency/price), o4-mini (cheap fast reasoning, depth ceiling vs o3). o-series have `reasoning_effort` param = `low`/`medium`/`high` (affects token usage not base price).
- **Use case 3A — Long-context agentic RAG (legal)**: no vector DB, no preprocessing; load whole doc (900k+ tokens TBMP), recursively split into 20 sentence-aware chunks (`split_into_20_chunks`, `min_tokens=500`), model picks relevant chunks, drill down `max_depth` levels to paragraphs.
  - Mechanism: router = `gpt-4.1-mini` two-pass — first a REQUIRED tool call `update_scratchpad` (`tool_choice="required"`) to record reasoning, then structured JSON chunk selection. Answer synthesis = `gpt-4.1` via `client.responses.parse(..., text_format=LegalAnswer)` (Pydantic). Verification = `o4-mini` LLM-as-judge → `VerificationResult{is_accurate, explanation, confidence:Literal[high/medium/low]}`.
  - "List of Literals" trick: dynamically build `List[Literal[...]]` of valid paragraph IDs to force citations to real IDs (restriction: breaks if >~500 options; fall back to regex-extract IDs from text).
  - Numbers: fixed cost traditional RAG ~$0.43 vs agentic $0.00; per-query ~$0.36 (routing $0.10 + two recursions $0.20 + synth $0.05 + verify $0.01). 20 chunks empirically chosen.
  - Caveats: higher per-query cost, higher latency, limited scalability for huge corpora.
- **Use case 3B — AI co-scientist (pharma, multi-agent)**: parallel role-playing `o4-mini` ideation agents (hypothesis/protocol/resource personas) → Elo-style pairwise **tournament ranking** (o4-mini/o3) → deep critique/synthesis by `o3` (senior-scientist persona) → optional `gpt-4.1-mini` safety check → mandatory human review → `o3`+Code Interpreter execution/learning loop to Outcome DB.
  - Mechanism: model IDs pinned `o4-mini-2025-04-16`, `o3-2025-04-16`, `gpt-4.1-mini-2025-04-14`. Tools grounded: `list_available_chemicals`, `chem_lookup`, `cost_estimator`, `outcome_db`, `literature_search` (mocked in tools.py). Model decides when/which tool.
  - Caveat/finding: 1-10 absolute scoring gave inconsistent "score compression"; pairwise tournament more reliable. Same model generating + critiquing → self-justification; separate persona/model for critique surfaces flaws o4-mini missed.
  - Cost control: configurable `Fast`/`Standard`/`Thorough` modes adjusting #agents, critique depth, optional checks; track tokens per stage & per tool call.
- **Use case 3C — Insurance OCR (vision + reasoning)**: two-stage — stage 1 `gpt-4.1` vision OCR into Pydantic schema (`InsuranceFormData`), preserving ambiguity ("l OR 1"); stage 2 `o4-mini` reasoning + function calling (`validate_email`, `search_web`) to resolve ambiguity/fill missing fields. Conversation loop via `client.responses.parse(... reasoning={"summary":"auto"})` handling `function_call_output`.
  - Chose two-stage because single o4-mini insufficient and o3 too costly. `detail:"auto"` on image input (use `high` if quality issues). temperature=0 for reproducibility.
  - Numbers: target <$20/1000 pages; actual $15.70/1000 (OCR $8.00 + reasoning $7.70) using batch pricing; single-stage o3 would be ~$70/1000. Metrics: OCR accuracy, inferred-field rate, human-intervention rate.
- Price table (Apr 2025, per 1M tok): GPT-4.1 $2/$8 (1M ctx), 4.1-mini $0.40/$1.60, 4.1-nano $0.10/$0.40, o3 $10/$40 (200K), o4-mini $1.10/$4.40 (200K).
- Prompt-pattern token/latency deltas: Self-Critique +20-30% tok; CoT +40-80%; Structured Outputs +5-10%; Zero-Token Memory -70-90%; Self-Consistency +200-300%; Tournament Ranking +50-100%.
- Prototype→production checklist: quantitative KPIs/SLOs, document model rationale, eval suite with 50-100 golden examples (factuality/hallucination/tool-error), cost guardrails + modes, HITL for high-risk, version pinning + A/B + rollback.
- Cited URLs: https://cookbook.openai.com/examples/orchestrating_agents ; https://cookbook.openai.com/examples/gpt4-1_prompting_guide ; https://cookbook.openai.com/examples/structured_outputs_multi_agent ; https://platform.openai.com/docs/guides/agents ; https://platform.openai.com/docs/guides/batch ; https://platform.openai.com/docs/guides/evals
- QMX-fit: Portfolio + Lab copilots (model routing/escalation), workflow agents (co-scientist multi-stage). LangChain/DeepAgents mapping (inference): escalation ladder = per-node model selection in StateGraph; tournament/critique = subagents/managed agents; HITL review = `interrupt`; "modes" = config keys; LLM-as-judge verify = separate grader node.

### openai-cookbook/examples/partners/self_evolving_agents/autonomous_agent_retraining.ipynb

- Core pattern: **self-evolving / autonomous retraining loop** — baseline agent output → human or LLM-as-judge feedback → evals/aggregated score → metaprompt rewrites system prompt → updated agent replaces baseline. Loop until score > threshold (`0.8`) or `max_retry` (10).
- Built on OpenAI **Agents SDK** (`from agents import Agent, Runner, trace`), `client.evals` API, and OpenAI Evals platform UI. Baseline agents authored in AgentBuilder UI (summarizer uses file_search over vector store; compliance checker vs FDA 21 CFR Part 11); GPT-5, low reasoning effort.
- Eval mechanism: `client.evals.create` with `data_source_config{type:"custom", item_schema}`; four graders in `testing_criteria`:
  - `python` grader `chemical_name_grader` (pass 0.8) — exact chemical-string preservation (CHEMICALS_MASTER list).
  - `python` grader `word_length_deviation_grader` (pass 0.85) — inverse deviation from 100-word target, 20% tolerance band.
  - `text_similarity` cosine (pass 0.85) — summary↔source cosine.
  - `score_model` LLM-as-judge (pass 0.85) — rubric score.
  - `image_tag:"2025-05-08"` on python graders.
- Runner helpers: `run_eval` → `client.evals.runs.create(data_source={type:"jsonl", source:{type:"file_content"...}})`; `poll_eval_run` polls `runs.retrieve` until `status=="completed"` (max_polls, sleep 5s), then `runs.output_items.list`; `parse_eval_run_output` extracts name/score/passed/reasoning. Caveat: Evals platform has **no API to retrieve user (thumbs) feedback programmatically**.
- Prompt versioning: Pydantic `PromptVersionEntry{version,model,prompt,timestamp,eval_id,run_id,metadata}` + `VersionedPrompt` manager for controlled updates/rollbacks (fallback history vs regression). `eval_cache` keyed by (section,summary) avoids redundant grader runs.
- Selection logic: `LENIENT_PASS_RATIO=0.75` (75% graders pass), `LENIENT_AVERAGE_THRESHOLD=0.85`; `best_candidate` tracks latest lenient pass but final pick uses aggregate totals; `apply_best_candidate_if_needed` restores top cumulative scorer (ties favor latest).
- Loop: `self_evolving_loop` wraps iterations in `with trace("Self-evolving Optimization Workflow")` (OpenAI dashboard tracing); `MAX_OPTIMIZATION_RETRIES=3`; `Runner.run(summarization_agent, section)`.
- Model comparison: `compare_model_candidates` optimizes prompt then grades across `["gpt-5","gpt-5-mini"]` and adopts top performer; references `ModelSettings` class. Caveat: cross-family model comparison should be pre-production only; prod testing within same family.
- Continuous monitoring: cron/scheduler loop (`continuous_monitoring(interval_hours=24)`) re-runs eval+optimization when `new_data_detected()`; monitor drift on blind datasets.
- **GEPA** (Genetic-Pareto) optimizer: `pip install gepa litellm`; `GEPAAdapter` with hooks `evaluate` (returns `EvaluationBatch` of scores+outputs+feedback trajectories), `get_components_to_update` (system_prompt), `make_reflective_dataset`. `gepa.optimize(seed_candidate, trainset, valset, adapter, reflection_lm="gpt-5", max_metric_calls=10, track_best_outputs=True)`. Train/val split (val_cut=10%). ~10-15 min run.
- Comparison of three optimizers: platform Optimize button (fast, not automatable), static metaprompt (automated but risks overfitting to grader feedback, section-by-section), GEPA (reflective, train+val, more generalizable/robust). Recommend combining: fast iteration → reflective.
- Numbers: thresholds above; quality stop >80% positive feedback; GEPA best prompt targets ~45-70 words (≤90).
- Caveats: optimization not always successful → rollback matters; grader fidelity is critical; needs guardrails + human approval of new prompts in real deployments.
- Cited URLs: https://arxiv.org/abs/2507.19457 (GEPA paper); https://github.com/gepa-ai/gepa ; https://openai.github.io/openai-agents-python/ref/model_settings/#agents.model_settings.ModelSettings
- QMX-fit: Lab copilot (workflow/experiment building), workflow/server agents (overnight continuous retraining). LangChain/DeepAgents mapping (inference): metaprompt loop = a meta-agent subagent; graders = eval nodes; VersionedPrompt = store/checkpointer-backed config history; continuous_monitoring = scheduled/long-running agent; GEPA = external optimizer feeding the store; trace = observability.

### openai-cookbook/examples/partners/temporal_agents_with_knowledge_graphs/temporal_agents.ipynb

- Two core patterns: (1) **Temporal Agent ingestion pipeline** building a time-aware KG; (2) **Multi-hop retrieval agent** (planner + orchestrator loop + tools) over that KG. Python 3.12+, Responses API, Pydantic, Jinja prompts, NetworkX/SQLite (prototype), Neo4j/pgvector (prod).
- Data: HuggingFace `jlh-ibm/earnings_call` (188 transcripts 2016-2020, AMD+NVDA subset). Pre-built DB on HF `TomoroAI/temporal_cookbook_db`. Inspired by Zep (arxiv 2501.13956) and Graphiti (getzep/graphiti, Apache-2.0).
- **Ingestion pipeline stages**: load → semantic chunk → statement extraction → temporal range extraction → triplet+entity extraction → TemporalEvent assembly → entity resolution → invalidation → DB write.
  - Chunking: `chonkie.SemanticChunker` + `text-embedding-3-small`, `threshold_value=0.7`, `min_sentences=3`, `num_workers=50`, ThreadPoolExecutor. `find_quarter` via regex `[Q]\d\s\d{4}`.
  - Classification enums: `TemporalType{ATEMPORAL, STATIC, DYNAMIC}`, `StatementType{FACT, OPINION, PREDICTION}`. Atemporal=universal truths, Static=point-in-time never changes, Dynamic=evolves.
  - Statement extraction = atomic subject-predicate-object claims, co-reference resolved to `main_entity`, acronyms expanded, split compound/multi-temporal sentences. Jinja prompt injects `LABEL_DEFINITIONS` (definition/date_handling_guidance/examples) + few-shot.
  - Temporal range: `RawTemporalRange{valid_at, invalid_at}` (date-time strings, structured-outputs `format:"date-time"`) → `TemporalValidityRange` (UTC datetimes). Prompt (adapted from Graphiti extract_edge_dates, Apache-2.0) enforces ISO-8601, anchors relative dates to publication date, quarter inference, no external knowledge; opinion→only valid_at, prediction→invalid_at=end of forecast window.
  - Triplets: `Predicate` StrEnum of 20 time-neutral predicates (IS_A, HAS_A, HOLDS_ROLE, PRODUCES, LAUNCHED, HAS_REVENUE, INCREASED, DECREASED, RESULTED_IN, SECURED, etc.) + `PREDICATE_DEFINITIONS`. Numeric values extracted as separate `Numeric` entities (name=units, numeric_value). `RawTriplet`/`Triplet`, `RawEntity`/`Entity`, `RawExtraction{triplets,entities}` extracted together per statement to cut LLM calls. Triplet prompt explicitly excludes temporal expressions.
  - Define-your-own-predicates workflow: run with `PREDICATE_DEFINITIONS={}` → review noisy graph → merge dupes (IS_CEO vs IS_CEO_OF) → finalize.
  - `TemporalEvent{id,chunk_id,statement,embedding(256-dim text-embedding-3-large),triplets,valid_at,invalid_at,temporal_type,statement_type,created_at,expired_at,invalidated_by}`.
  - `TemporalAgent` uses `AsyncOpenAI`, model `gpt-4.1-mini`, Jinja `DictLoader`, tenacity retry (`wait_random_exponential min1 max30, stop_after_attempt(3)`). Embeddings `text-embedding-3-large dimensions=256`.
- **Entity resolution**: `EntityResolution` batches by `Entity.type`, RapidFuzz partial-ratio clustering (threshold 80.0), medoid as canonical, acronym cross-check (`acronym_thresh=98.0`), links aliases via `resolved_id`. Suggest embedding-based or LLM grouping as upgrade.
- **Invalidation Agent** (`gpt-4.1-mini`): bidirectional check (incoming-vs-existing and existing-vs-incoming). Only DYNAMIC, FACT, non-ATEMPORAL events eligible; candidates must share ≥1 canonical entity, same `PREDICATE_GROUPS` bucket (4 groups listed), temporally overlap+ongoing, cosine sim > `_similarity_threshold=0.5`, keep `_top_k=10`. On invalidation set `invalid_at`=secondary's valid_at, `expired_at`=now, `invalidated_by`=secondary id. Prompt rules: no external knowledge, cannot invalidate chronologically-later event, cannot self-invalidate, can only refine invalid_at earlier. Dedup: one invalidation per event, earliest time. Efficiency upgrade noted: 1:many instead of 1:1, network clustering/batching.
- Numbers (ingestion): ~2-5 min/transcript, ~30 files ≈ up to 2h; NetworkX good <~100k nodes.
- **Model selection for Temporal Agent**: prototype GPT-4.1 → swap to 4.1-mini/nano → distill onto mini/nano (teacher=4.1). Cited GPT-4.1 beats GPT-4o by 10.5%abs on Scale MultiChallenge.
- **Multi-hop retrieval agent**: user question → `initial_planner` (GPT-4.1, persona of internal financial expert, outputs "Research tasks" plan) → orchestrator loop (GPT-4.1 / o4-mini) issuing tool calls → loop until answer. `parallel_tool_calls=False`. `MultiStepRetriever.run` with `function_map`.
  - Planner types: **task-oriented** (deterministic subtasks, used here) vs **hypothesis-oriented** (testable claims, open-ended research). Plan static here; replanning noted for longer horizons; optional user plan-editing HITL.
  - **Tool design spectrum**: Fixed (rigid, few args) / Semi-structured (used; specialized sub-agent tools or flexible-arg interfaces) / Free-form (code interpreter). Prod prefers semi-structured (templated Cypher) over free-form for reliability.
  - Tools: `factual_qa(entity,start_date_range,end_date_range,predicate)` — 4 steps: predicate coercion via GPT-4.1-nano structured output (`PredicateMatching`) + `PredicateMatchValidation` field_validator, fuzzy entity match, inbound/outbound edge collection, format. `trend_analysis(question,companies,topic_filter[],...)` wraps factual_qa across (company,predicate) pairs concurrently (`asyncio.gather`), summarized by **o4-mini high reasoning effort**. JSON function schemas given (`type:"function"`, `additionalProperties:False`).
- **Model selection for retrieval**: start o3 (prototype / complex legal-pharma data / golden-set gen) → o4-mini main prod engine (prompt tuning + RFT) → GPT-4.1 when latency dominates. RFT: as few as ~50 golden answers, no step-by-step trajectories needed (only final answer).
- Evaluation: (1) human golden answers (precision@k/recall@k; reliable but costly/stale), (2) synthetic (LLM-as-judge or tool-use pathway scoring; fast/scalable, lower quality), (3) human feedback (thumbs/ELO; real-world but noisy). Recommended: synthetic → golden before deploy → live feedback.
- Prototype→prod (appendix): pgvector index types — flat (exact, <100K), ivfflat (`lists`/`probes`, 100K-200M), ivfpq (`subvectors`/`bits`, memory-efficient 1M-500M), hnsw (`M`/`ef_construction`/`ef_search`, billions, lowest latency). B-tree on valid_from/valid_to; non-destructive updates (status=inactive); PARTITION BY RANGE(valid_from). Vector DBs compared: Pinecone/Weaviate/Milvus/Qdrant/Vectara.
  - Concurrency: staged pipeline, per-stage queue+worker pool (Redis/SQS), batch chunking (100-500), extraction batches (50-100) with semaphore rate limiting, invalidation grouped by entity cluster, ANN entity resolution. Benefits: throughput, independent scaling, backpressure.
  - Cost: prompt caching keyed `md5(statement_text)` (Redis/LRU); `service_tier="flex"` (Responses API) up to 40% savings for short extractions; replace generation calls with embeddings+pgvector NN. Relevance-based pruning: `relevance_score = β1*recency + β2*source_trust + β3*retrieval_count`; sparsify/coarsen/condense (arxiv 2402.03358); shadow-mode validate; nightly re-score. TTL/archival jobs.
  - Safeguards: multi-layer output verification (ISO-8601 check, controlled-vocab entity types, cheap-model sanity check), structured logging + OpenAI tracing, KPI monitoring. Prompt optimization: personas, 2-5 few-shot, CoT for temporal reconciliation, reusable prompts + A/B + rollback (invalidation accuracy <90% → alert/rollback).

### openai-cookbook/examples/partners/agentic_governance_guide/agentic_governance_cookbook.ipynb
- Multi-agent triage with handoffs: a `PEConcierge` triage `Agent(handoffs=[...])` routes to 3 specialist agents; routing decided by each specialist's `handoff_description` (authors stress this field is critical for routing).
- SDK mechanism: `from agents import Agent, Runner, function_tool, trace, InputGuardrail, GuardrailFunctionOutput`; tools are `@function_tool`-decorated funcs whose docstring = tool description; `await Runner.run(agent, input)`, `result.final_output`.
- Model strings `gpt-5.2` / `gpt-4.1-mini` / `gpt-5.2-mini` (post-cutoff names, treat as illustrative/UNVERIFIED).
- Two guardrail layers: (1) agent-level built-in via `input_guardrails=[InputGuardrail(guardrail_function=...)]`; a guardrail agent with `output_type=PydanticModel` returns `tripwire_triggered`; raises `InputGuardrailTripwireTriggered` / `OutputGuardrailTripwireTriggered`. (2) org-wide `openai-guardrails` library: `GuardrailsOpenAI(config=POLICY)` wraps the OpenAI client, applies policy to every call; `GuardrailTripwireTriggered`. `GuardrailAgent` is the Agents-SDK-integrated variant.
- Policy JSON has 3 stages: `pre_flight` (PII `Contains PII` with entity list + `block:true`, `Moderation` categories), `input` (`Jailbreak`, `Off Topic Prompts` with `confidence_threshold`, `model:"gpt-4.1-mini"`), `output` (PII with `block:true` to actually block vs mask). Wizard at guardrails.openai.com exports this JSON.
- Policy-as-package pattern: `pe_policies/__init__.py` loads `config.json` → `GUARDRAILS_CONFIG`; `pip install git+https://github.com/...`; Git history = audit trail; versioned/upgradable.
- Tracing: `with trace("name"):` groups spans (LLM calls, tool calls, handoffs, guardrails) viewable at platform.openai.com/traces; descriptive trace names recommended.
- ZDR (Zero Data Retention) options: disable globally, or per-run `RunConfig(tracing_disabled=True)`, or custom processor `add_trace_processor(exporter)` with `on_trace_start/on_span_start/on_span_end/on_trace_end` to stream to Datadog/Splunk/ELK and redact PII.
- Guardrail evals framework (`openai-guardrails[benchmark]`, needs sklearn): dataset JSONL `{id,data,expected_triggers:{name:bool}}`; metrics precision/recall/F1 + TP/FP/FN/TN per stage/guardrail. CLI `guardrails-evals --config-path --dataset-path --output-dir`; programmatic `GuardrailEval(..., batch_size=10, mode="evaluate")`; `--mode benchmark --models gpt-5.2-mini gpt-5.2` compares models + ROC. Advice: "evaluate what you deploy" (reuse prod policy as eval config).
- Automated threshold tuning: `GuardrailFeedbackLoop(config_path,dataset_path,output_dir,precision_target=0.90,recall_target=0.90,priority="f1",max_iterations=5,step_size=0.05)`; starts thresholds at 0.95 to demo lowering for recall; has oscillation prevention (shrinks step, stops). Outputs `eval_config_tuned.json` + `tuning_report_*.md`.
- Red teaming: Promptfoo (`pip install promptfoo`, needs Node 20+); `redteam` with `plugins` (hijacking, pii:direct, prompt-extraction, system-prompt-override, off-topic, policy) + `strategies` (jailbreak, prompt-injection, base64, leetspeak, rot13, crescendo). 131 plugins; presets `owasp:llm`, `nist:ai:measure`, `mitre:atlas`. Target script bridges Promptfoo→`Runner.run(pe_concierge_governed, prompt)` returns `[BLOCKED]` on tripwire.
- Numbers: eval dataset 21 samples (and 16 input-guardrail: 8 jailbreak/8 clean); `confidence_threshold` 0.7 default / 0.95 high / 0.5 sensitive; sample report "33/33 tests defended, 0 vulnerabilities"; ~100-200 API calls / few dollars for `numTests:10` across ~9 plugins.
- Caveats: OpenAI does NOT execute tools — it names tool+args, your code runs them; precision/recall tradeoff on threshold; `block:true` required or PII only masked.
- Governance-at-scale guidance: Agent/Tool/Prompt registries (owner, risk tier, eval status), risk-proportionate controls (low/moderate/high), prevent shadow AI, NIST AI RMF / ISO 42001 alignment.
- URLs: https://openai.github.io/openai-agents-python/ ; https://openai.github.io/openai-guardrails-python/ ; https://guardrails.openai.com/ ; https://www.promptfoo.dev/docs/red-team/ ; https://modelcontextprotocol.io/
- QMX-fit: general copilot (safety/routing) + Portfolio copilot (finance-domain triage). LangChain/DeepAgents mapping (inference): triage+handoffs → DeepAgents subagents or LangGraph router node; input/output guardrails → middleware wrapping the model node; policy-as-package → shared config in store; `trace()` → LangSmith/OTEL tracing; ZDR custom processor → custom callback handler.

### openai-cookbook/examples/partners/AWS/chatgpt_agents_sdk_aws_agentcore_cookbook/README.md
- Pattern: expose read-only `@function_tool`s from an Agents-SDK agent as an MCP server, reach it from ChatGPT via Secure MCP Tunnel; model served by Amazon Bedrock through OpenAI-compatible endpoint; optional managed hosting via AgentCore Runtime.
- Components: MCP adapter (Node, FastMCP-style, validates in/out against strict schemas), widget (HTML view in ChatGPT, renders tool result, no backend calls), local Agents-SDK agent, tracing (spans for agent/model/tool).
- Three tools: `search_flights`, `get_upcoming_status`, `get_live_status` — deterministic sample data, cannot book/change/cancel (read-only design principle).
- Execution modes: `COOKBOOK_EXECUTION_MODE=local` (checked-in agent on workstation) vs `deployed` (invoke existing AgentCore Runtime ARN, invoke-only role; Runtime owns model creds + telemetry).
- Model config: `OPENAI_BASE_URL=https://bedrock-mantle.<region>.api.aws/v1`, `OPENAI_AGENTS_MODEL=openai.gpt-oss-120b`, Bedrock-issued `OPENAI_API_KEY`. Key separation: `OPENAI_API_KEY` (Bedrock, model) vs `OPENAI_TRACE_API_KEY` (OpenAI Platform, traces, dual mode only) vs `CONTROL_PLANE_API_KEY` (tunnel runtime).
- Tracing: `COOKBOOK_TRACING_MODE=aws|dual`. Local ADOT publishes to CloudWatch/X-Ray service `chatgpt-agentcore-cookbook-local`; dual also exports OpenAI Traces workflow. Privacy defaults: `OPENAI_TRACE_INCLUDE_SENSITIVE_DATA=0`, `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=false` (records session/trace/span/tool/timing/error/usage, NOT raw prompts/responses).
- Session: stable hashed `chatgpt-...` session id when ChatGPT supplies `openai/session`; else new id per invocation (ungroupable).
- MCP server on loopback `http://127.0.0.1:8787/mcp`; health `/`→`{"status":"ok","mcp":"/mcp"}`; tunnel client `/readyz` on 8080; tool listing via `@modelcontextprotocol/inspector --transport http --method tools/list`.
- Evals: Promptfoo is primary (actual-agent eval), `npm run eval:agent` with `RUN_PROMPTFOO_AGENT_EVALUATION=1` (calls Bedrock); plus optional on-demand AWS AgentCore built-in evaluators `Builtin.Correctness`, `Builtin.GoalSuccessRate`, `Builtin.TrajectoryExactOrderMatch` (needs content-capture confirmed + separate eval role). Fixtures `flight-status-results.jsonl`.
- Caveat stressed repeatedly: a successful agent response is NOT proof of trace ingestion ("trace verification is a separate step"); verify via correlation_id in CloudWatch span log group.
- Least-privilege IAM matrix: scoped `logs:`/`xray:`/`cloudwatch:PutMetricData`; `bedrock-agentcore:InvokeAgentRuntime` must authorize BOTH parent Runtime ARN and endpoint ARN; `logs:GetQueryResults` needs `Resource:"*"` (no scoping).
- Caveats: `.env` must be chmod 600 and gitignored; exported shell vars override `.env`; restart MCP server after `.env` change; WSL 2 for Windows.
- URLs: https://developers.openai.com/api/docs/guides/secure-mcp-tunnels ; https://github.com/openai/tunnel-client/releases/latest
- QMX-fit: workflow/server agent (QMX desktop copilot exposing read-only broker/market tools) + general copilot. LangChain/DeepAgents mapping (inference): MCP adapter → LangChain MCP tool adapter (`langchain-mcp`); read-only tool design → QMX "UI over API door" + no-CLI rulings; dual tracing → LangSmith + local OTEL; AgentCore Runtime ≈ QMX remote background-workflow server.

### openai-cookbook/examples/partners/AWS/evidence_grounded_aml_agent_with_bedrock.ipynb
- Pattern: regulated-investigation agent with 4 separated boundaries — deterministic evidence / model proposal / application controls / human authority. Finance/compliance (AML/SAR).
- SDK mechanism: `Agent[InvestigationContext](name, model, model_settings, output_type=RiskAssessment, tools=[...], instructions=...)`; typed generic context; `Runner.run(..., context=instance)`; tools read context via `RunContextWrapper[InvestigationContext]`; `ModelSettings(reasoning=Reasoning(effort="medium"), store=False)`.
- Bedrock client: `AsyncOpenAI(provider=bedrock(region=...))`; `set_default_openai_client(client, use_for_tracing=False)`, `set_default_openai_api("responses")`; preflight lists models via `bedrock-mantle` discovery endpoint before paid inference. Model `openai.gpt-5.6-sol` (post-cutoff, UNVERIFIED).
- Tools: `@function_tool(failure_error_function=None)` so evidence-tool exceptions PROPAGATE instead of becoming model-visible error strings (deliberate — keeps bad reads from being silently reasoned over).
- Output schema (Pydantic) enforces structure AND authority limits: `RiskAssessment` with `findings: list[Finding]` (each carries `evidence_ids`, computed values), `drafting_authorized: Literal[False]`, `filing_decision: Literal["NOT_DETERMINED"]` — schema literally prevents the model from granting itself authority.
- Validation (the key lesson): correctness comes from DETERMINISTIC support checks, not the model/schema. `validate_risk_assessment` does 3 checks: citation validity (IDs exist), claim support (recompute cash_credit_count/total, outbound_wire, movement_ratio and compare), structured authority denied. A valid transaction ID alone does NOT prove support; `math.isclose(abs_tol=0.1)`.
- Human-in-the-loop gate owned by APPLICATION, not model: `record_human_review` (APPROVE/REJECT_DRAFTING), `require_drafting_allowed` checks latest review event approves THIS revision; rejection persists in `review_history`, never overwritten; revised analysis needs explicit re-review (`submit_revised_analysis`).
- Drafting agent defined only AFTER approval gate; `get_reviewed_analysis` tool returns analysis only if `require_drafting_allowed` passes; drafting agent has no approve/state-change/file tool. Pre-store verification walks raw run-item payloads (`ToolCallItem`/`ToolCallOutputItem`, `completed_function_tools`) to confirm every required evidence call produced output.
- Default path is fully offline deterministic fixture (no AWS/model call) — explicitly "does not prove Agents SDK orchestration"; paid paths gated by `RUN_ANALYSIS_DEMO` / `RUN_DRAFTING_DEMO`.
- Negative tests: fabricated amount (real IDs, wrong value), invalid citation, missing tool call, structured-authority claim — each a separate failure mode.
- Caveats: learning asset not production; real deployments need identity/authz, durable audit, expert-reviewed evals. Signals ≠ intent/wrongdoing/filing requirement.
- URLs: https://developers.openai.com/api/docs/guides/amazon-bedrock ; https://developers.openai.com/api/docs/guides/agent-evals ; https://www.fincen.gov/suspicious-activity-reports-sars
- QMX-fit: Portfolio copilot (risk/sizing with hard money boundaries) — strong template for QMX's "risk authority in docs, chat barred" + money-path boundary rulings. LangChain/DeepAgents mapping (inference): typed context → LangGraph state (TypedDict) + per-request instance; deterministic validator → post-model tool/validation node that gates transitions; human gate → LangGraph `interrupt()` + checkpointer persisting review_history; authority-denying schema → structured output with Literal constraints.

### openai-cookbook/examples/partners/eval_driven_system_design/receipt_inspection.ipynb
- Pattern: eval-driven lifecycle (not an agent loop) — V0 skeleton → label with experts → initial evals → map evals to business $ → iterate → productionize. Two-stage pipeline: `extract_receipt_details` (image→structured) then `evaluate_receipt_for_audit` (structured→decision).
- Mechanism: `client.responses.parse(model, input=[...multimodal input_text+input_image data URL...], text_format=ReceiptDetails)` → `response.output_parsed`; Pydantic structured outputs. Models `o4-mini` (default dev), `o3` (most capable baseline), `gpt-4.1-mini` (cheaper prod).
- OpenAI Evals API: `client.evals.create(name, data_source_config={type:"custom", item_schema=Model.model_json_schema(), include_sample_schema:False}, testing_criteria=graders)`; run `client.evals.runs.create(eval_id, data_source={type:"jsonl", source:{type:"file_content", content:[{"item":...}]}})`; `eval_run.report_url`. `{{ item.field }}` Jinja templating over `EvaluationRecord`.
- 3 grader types (18 graders total): `string_check` (operation eq), `text_similarity` (`evaluation_metric:"bleu"`, `pass_threshold:0.8`), `score_model` (LLM judge, `model:"o4-mini"`, `range:[0,1]`, `pass_threshold:1`, prompt scores 0/1). Prediction can be an arbitrary system (supply full item) not just one model call.
- Multi-step eval insight: evaluate end-to-end AND each step conditioned on prior output — don't train the auditor to ignore its (misleading) inputs; a factually-wrong AuditDecision can still yield the correct decision.
- Business model ties evals to dollars: `calculate_costs(fp_rate, fn_rate, per_receipt_cost)`; 1M receipts/yr, audit $2, missed audit $30, 5% need audit; baseline perfect $100k vs current $135k+$45k+$200k human. "Not all evals matter" — merchant-name 85% wrong but uncorrelated with audit decision → don't fix; handwritten-X misses cost $75k, OCR math errors up to $400k.
- Model-improvement waterfall (order): 1 model selection/reasoning budget, 2 prompt tuning, 3 examples/context (few-shot, RAG), 4 tools, 5 accessory/guardrail models (MoE), 6 fine-tuning (SFT/RFT/DPO). Always optimize prompt before fine-tuning. Same graders reusable for Reinforcement Fine-Tuning (keep separate train data, no eval leakage).
- Numbers: 20 samples (8 pos/12 neg); `o4-mini`→`gpt-4.1-mini` ≈ 2/3 inference-cost cut; per-receipt ≈1¢ (o4-mini) / 0.3¢ (4.1-mini); eval spend $10+/day/engineer typical, $100+ unsustainable; flywheel: label inputs where models disagree (dumb+smart agree → easy), distillation at the end.
- Caveats: strings not Decimal/datetime (deserialize poorly); small sample → unreliable 0 false-negative rate; ZDR keeps Evals data to maintain state.
- URLs: https://platform.openai.com/docs/guides/graders ; https://cookbook.openai.com/examples/reinforcement_fine_tuning ; https://labelstud.io/
- QMX-fit: Lab copilot (building/evaluating QMX strategies & mini-apps), cost-control across cheap/expensive models. LangChain/DeepAgents mapping (inference): no direct agent loop; graders → LangSmith evaluators/custom eval harness; structured output → `with_structured_output`; business-cost model → custom metric layer; model waterfall → model-tier selection matching QMX Opus-vs-DeepSeek split.

### openai-cookbook/examples/partners/harness_aware_plugin_evals/harness_aware_plugin_evals.ipynb
- Core thesis: a plugin's eval score measures the SETUP (harness) as much as the model; run the same cases at 3 fidelity levels and localize each difference to the level that caused it.
- 3 levels: (1) Direct tool tests — call `resolve` directly, no model/network, deterministic, free, CI-droppable (`level_one.py`, exits non-zero on fail); (2) Standalone function-calling loop — app-owned loop over Responses API + MCP tools, moderate cost, own system prompt; (3) Product harness (Codex) — same queries through Codex SDK with plugin installed, highest fidelity/cost.
- Terms kept distinct: Tool (one function+schema) / MCP server (process publishing tools) / Plugin (bundle+metadata) / Harness (agent loop, prompt formatting, tool execution, turn limits, sandbox).
- Example MCP server (FastMCP over HTTP, `server.py`): `resolve(indicators)`→ranked candidate BLS series w/ confidence; `fetch_bls_data(series_ids)`. Synthetic fixtures reproduce 3 properties: ambiguous default (unemployment, adjusted vs unadjusted), true ambiguity (employment, two tied, no default), coverage gap (CPI, empty list).
- Standalone loop mechanism: `AsyncOpenAI` + MCP `Client`; `mcp.list_tools()`→`{"type":"function","name","description","parameters":tool.inputSchema}`; `openai.responses.create(input=conversation, ...)`, filter `item.type=="function_call"`, run `mcp.call_tool(call.name, args)`, append `function_call_output`; carries whole convo in `input` with `store:False` (works on ZDR key); `model_dump(exclude_none=True)` (API rejects null-valued round-tripped fields).
- Grader (`eval_grading.py`, shared by levels 2&3): checks TOOL CALLS not answer text — expected tools ran, expected series returned, "no other series fetched" (catches invented IDs next to real), non-empty final answer. Cannot verify answer correctness → shipped eval also needs an answer-level/LLM-rubric check.
- Codex provider: Promptfoo `openai:codex-sdk`; `config.toml` permission profile `default_permissions="eval"` with `[permissions.eval.filesystem] ":workspace_roots"="deny"` — locks dir so a model with shell can't read `promptfooconfig.yaml` (answers) or `.env` (key); MCP-over-HTTP still works. `CODEX_HOME` must be the isolated home or plugin doesn't load. `enable_streaming:true` retains item stream; assertion reads `mcp_tool_call` items, normalizes to `{name,arguments,result}`. ChatGPT `@BLS` prefix injected via `defaultTest.options.prefix: "[@BLS](plugin://BLS@cookbook-plugins) "`.
- Key fix mechanism: MCP servers send an `instructions` field in the `initialize` handshake response (spec: hint a client MAY add to system prompt). Codex reads+passes it to the model; the standalone loop ignores it (uses own system prompt). Setting `FastMCP("BLS...", instructions=GUIDANCE)` makes all 5 Codex cases pass with NO tool/resolver change. Must restart server (instructions sent only at initialize).
- Numbers: 5-case example — standalone 5/5, Codex 3/5 before guidance (CPI invents `CUUR0000SA0`, employment fetches instead of clarifying), 5/5 after. Production: 108 questions / 56 surveys, LLM rubric judge `gpt-5.6-sol`, Codex 0.159.2, promptfoo 0.123.1. Table1: GPT-6.1 Sol 0.94 (4.02 tool calls, 19 reasoning tokens), GPT-6 Astra 0.94 (3.74, 14), GPT-6 Luna 0.88 (5.54, 1229). Table2 harness gap: Luna 0.88 Codex / 0.74 loop; GPT-5-mini 0.43 Codex / 0.64 loop (mini LOSES 21pts under Codex — shell misuse, ~half failures involve shell doing nothing). Table3 non-determinism: 3 repeats 0.88/0.89/0.86 but 23/108 (21%) flipped pass↔fail; one question 5 vs 19 tool calls. Case ~10s Codex / 25s loop. All model names post-cutoff → UNVERIFIED.
- Caveats: treat pass rates as RELATIVE; aggregate stability can mask per-case churn → measure repeat-stability as its own metric; cheaper harness/smaller model only approximates ship config; write cases where a plausible answer is wrong (short-list / clarify / no-data) and tag `mechanism`+`expected_type`.
- URLs: https://arxiv.org/abs/2407.01502 (AI Agents That Matter) ; https://arxiv.org/abs/2406.12045 (τ-bench, `pass^k`) ; https://www.promptfoo.dev/ ; https://developers.openai.com/codex/concepts/sandboxing ; https://gofastmcp.com/
- QMX-fit: workflow/server + Lab copilot (evaluating QMX agents before they ship; harness = QMX desktop). LangChain/DeepAgents mapping (inference): the 3-level idea maps directly — level1 = unit-test tools, level2 = LangGraph app loop, level3 = full QMX harness; MCP `instructions` → system-prompt middleware / tool descriptions; permission `deny` → sandbox/tool-allowlist; grader-on-tool-calls → LangSmith trajectory eval.

### openai-cookbook/examples/partners/macro_evals_for_agentic_systems/macro_evals_for_agentic_systems.ipynb
- Pattern: MACRO evals — move from thousands of agent events to a few population-level behavior patterns for both technical + business stakeholders. Two levels: lower-level evals (grade individual agents/handoffs/tools/runs via Promptfoo) → macro evals (cross-run clustering + diagnosis).
- 4 reader labels: `case_type` (generated situation) → `run_outcome` (completed/awaiting_review/blocked/failed) → `eval_finding` (local symptom) → `behavior_pattern` (discovered cross-trace pattern). First 3 known pre-clustering, 4th after.
- Simulated system = EV order swarm mapped to Agents SDK: orchestrator + specialists (validation, supply risk, procurement, capacity, factory routing, market intel, pricing, compliance, comms, release review); uses agents, handoffs, function tools, guardrails/review thresholds, structured outputs, traces. A "bundle" = full evidence packet per order (events, spans, handoffs, env signals, review packet, terminal state).
- Lower-level Promptfoo rubrics: `final_decision_quality`, `policy_compliance_correctness`, `routing_specialist_activation`, `market_drift_awareness`, `review_appropriateness`. Produce `eval_finding`.
- Pipeline (helpers `data_prep.py`, `macro_eval_pipeline.py`): `normalize_bundle`→`traces_df` (1 row/run) + `events_df` (1 row/event); build trace documents (`doc_structured_summary`: scenario, routing, state transitions, handoffs, findings, terminal state — document design IS part of eval design).
- BERTopic-style discovery: embed doc `e_i=f(d_i)` → UMAP reduce → HDBSCAN cluster (noise=-1) → class-aware term score `score(t,k)=tf(t,k)·log((1+N)/(1+df(t)))`. Triage rank `impact_score(k)=prevalence_share(k)·severity_weighted_prevalence(k)`. `run_macro_discovery(df, document_column, min_cluster_size, n_neighbors, top_n_terms, random_state)`; run only on failure/review/runtime/promptfoo-failed traces.
- Cohort lift: `lift = slice_pattern_share / overall_pattern_share` (>1 concentrated in slice); heatmap behavior_pattern × case_type; two Sankey plots (before: case→outcome→finding; after: +behavior_pattern).
- AgentTrace-style diagnosis: build execution graph G=(V,E) (events linked by temporal order/handoffs/tool calls/context); pick focus/anchor event (review/finding marker, failure, late decision); walk backward scoring suspects `suspect_score = 0.4·proximity + 0.3·frequency + 0.2·bridge + 0.1·role`. `drill_down_topic_root_causes(discovery, events_df, topic_id, top_n_traces=12, max_depth=5)`; outputs suspect leaderboard + story strip + swimlane.
- Numbers: 1000 synthetic orders, 992 bundles; `MACRO_EVALS_TRACE_LIMIT=48` smoke test; `final_decision_quality` dominant finding; lift≈1 baseline.
- Caveats: not a perfect taxonomy; impact_score is a prioritization heuristic not a risk formula; focus events are observability signals not root cause; suspect score not causal proof; better documents > fancier clustering.

### openai-cookbook/examples/partners/mcp_powered_voice_agents/mcp_powered_agents_cookbook.ipynb

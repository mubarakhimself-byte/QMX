## Governing distinction

Main `c3e8ec5ef33d0b38cdf7f5dbdd48a6fc70ac33cf`, `docs/contracts/ct-10-source-observation.yaml` defines **known_at as when the fact became knowable to QMF**, separately from event time and receive wall time; all three are durable identity-bearing fields. CT-12 requires knowledge-time partition, explicit stored boundaries, immutable calendar/world/role, purge/embargo and seal. Main `docs/components/qma-daemon.md:80-82` and the adopted backend `a0e8769` QMA `ARCHITECTURE-SPINE.md` AD-6 bind daemon folds to **recorded_at <= as_of**, ordered by journal_seq with equal instants ascending sequence. These are complementary owner contracts. The backend is published authority, not an unadopted BMAD suggestion; supporting notes alone cannot override them.

The cut is not the final source event, registry creation timestamp, split boundary, current wall clock or CT-13 terminal instant. Do not stamp an external QMF fact with a daemon recorded_at it does not have. Conversely, QMF known_at alone does not establish when a daemon-owned artifact/context entered QMA's approved view. Later computation/output can legitimately use earlier knowable inputs; newly materialized results are not required to have existed at the input cut.

## Implementable minimum and remaining proof gap

The source-fact half is implementable with existing typed values and physical reads: resolve the exact descriptor/request, reopen its CT-10 archive key list through the configured seal, reconstruct full SourceObservations, recompute the recorded-source fingerprint and compare each known_at to the approved Instant. Reject unavailable/malformed/foreign/corrected-unresolved facts and incompatible CT-12 role/world/calendar/horizon before evaluation. `Instant.try_create` is the existing exact int64 UTC-ns parser; the public timestamp parser must preserve the original optional input/full InputHash while providing this typed cut. A matching cut later than all selected known-at values is valid; equality to the final event is unnecessary.

The **whole pinned-frontier** assertion is not already proved by those fields alone. Registry occurrence sidecars and an AsOfSet can support the existing owner registry-before-instant check, while request/split/descriptor/interpreter/metadata identities prove content. To assert their availability in the approved QMA context, join the actual selected immutable artifact/reference binding to its genuine daemon admission/announcement journal record and approved scope. For QMA independent artifact evidence, use the existing closed `artifact_store` announcement path; do not invent a new independent store, event vocabulary or worker timestamp. Reopen the artifact and recompute its fingerprint, verify the announcing payload's record_fp1 and actual full pinned reference set, and require that journal record's recorded_at <= cut. Apply the declared journal-sequence fold law; a coincident timestamp or unrelated announcement does not link evidence.

This inspection does **not** find a complete existing immutable cut→all-selected-descriptor/set/request/split/source receipt join at the operator interfaces. Execution must identify the actual normal QMA admission artifact that carries that complete binding and preserve it through preflight/expected artifact/JobHandle/producer verification. If a required join is absent, return a typed unsupported/missing-proof refusal before acceptance/domain effects until that owner path is completed. New materialization after the cut is lawful when it is merely an exact derivation of the admitted earlier facts; do not demand its output creation time <= cut. No general requirement is invented that every external raw archive already have a QMA announcement: the announcement requirement applies to daemon-owned knowledge assertions and the declared closed QMA stores, not a replacement QMF intake model.

Keep current Mission/Task/actor/instance/grant/revision/attempt/occupancy authority current. Input knowledge cut does not restore obsolete grants/leases. Preserve complete approved context and optional as_of presence in expected result/CT-11 proof and actual producer occurrence; verify the same pinned evidence on restart and claimed/claimless result paths. No CT-12 boundary rewriting, raw known-at default, registry-as-of/event-time shortcut, receipt metadata synthesis, or new public query shape is justified.

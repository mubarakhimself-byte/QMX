## Bounded ATC runtime interface proposal

Authority: aligned architecture-QMX-2026-09-18/CONTRACTS.md §11, ADR-0024 A1 and existing qmb/config/alternative.py. AlternativeRunConfig remains a separate class, with Book/BMS/bot keys absent. Existing simulate_alternative_run creates identity/token/lineage objects only; it does not execute economic policy or persist CT13 evidence.

Minimal internal module: qmb.execution.alternative. Registry registration requires exact `(policy_pair_id, policy_pair_version, policy_pair_hash)` plus an explicit interpreter implementation. A typed evaluator receives validated AlternativeRunConfig, the current recorded CT10 observations/frontier and previous immutable accounting state, and returns new accounting state, risk verdict and internal simulated actions. Unsupported policy identity or observation shape refuses before effects. Registered implementation must interpret the exact accounting/risk field values; generic lifecycle never supplies a guessed fraction, gross-limit convention, fill/mark default or financial parameter grammar.

Composition runner resolves actual CT10 records through existing QMF reader, verifies composition and PolicyPair canonical hashes, host admission/grant/health freshness, internal-simulate capability and command-owner epoch. Each deterministic evaluation records exact policy identity, source/input hashes, frontier, prior/new state hashes and genuine verdict/actions to actual QMF CT13 JournalWriter; append refusal blocks acceptance. Return an ATC-specific result with real journal/event fingerprints and actual evaluator output identity. Do not mint CT32 Book/BMS performance results or fabricate Book bindings. Preserve configured cancellation/terminal outcomes and refuse paper/live until their separate authoritative admission/adapter requirements hold. Interpreter registration belongs to trusted application composition; caller payload cannot inject executable code or replace interpreter identity.

This is a generic lifecycle boundary, not a ratified numeric interpretation of example `fixed-fraction`/`max_gross` strings. A concrete interpreter needs explicit configured financial grammar and exact QMF numeric arithmetic. No new component, public contract or store is needed.

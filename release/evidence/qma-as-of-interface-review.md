## Authority and distinct frontiers

Governing main tree: `c3e8ec5ef33d0b38cdf7f5dbdd48a6fc70ac33cf`. CT-40 declares canonical payload transport, durable command identity, unchanged downstream correlation, and snapshots authoritative over progress. ADR-0024 DEC-0416/0437 requires the versioned operation descriptor and InvocationEnvelope on every public call; parameter authority is the operation input schema. DEC-0421/0442 makes ProductSession an authority overlay with context/grants and CAS, not a tab. ADR-0025 DEC-0463/0464 retains instance identity on every invoke, including home authoring's exact selected instance, and prohibits nested grant union. ADR-0026 DEC-0505 explicitly says no existing component's authority shrinks. These are governing adopted main requirements; source fixtures and BMAD support do not supersede them.

The backend `a0e8769` QMA architecture spine's AD-6 record/fold law and AD-7 actor ontology independently bind the knowledge cut and actor semantics. Its AD-6 states `as_of` bounds `recorded_at`, ordered by `journal_seq`, equal instants by ascending sequence. AD-7 makes ActorId opaque; desk membership must be resolved from the Quant definition, never inferred from its spelling. This adopted backend authority must remain alongside the later ProductSession/instance/grant overlay; passing a session or instance check cannot replace Task/Mission/actor/lease authority.

## Observed transport gap

`qma/core/operations/catalog.py` declares optional `as_of` for `qmb.backtest.run` and other operations. `qma/wire/invocation_envelope.py:940-981` validates allowed input keys and hashes the complete validated payload. For backtest, omitted versus supplied `as_of` currently yields different content; no backtest default adds it. Preserve that distinction. Do not delete the key to make a supplied request look like an omitted request. Canonicalizing the timestamp after the envelope is hashed requires an explicitly consistent caller/gate hash contract; parsing into a typed Instant internally need not rewrite the original validated input.

`sessions/product_session.py:604,750,1048,2384` parses UTC-Z context time, compares it to bound context, and constructs the top-level binding call. The optional **operation payload** and top-level **session binding** are distinct paths: `bind_granted_public_call` defaults its binding `as_of` from the session, while forwarding `payload` separately into public dispatch. Support must explicitly compare any supplied payload cut to that approved context; simply retaining the existing top-level comparison is insufficient. `process.py:3046` currently mints app-use context from a durable journal stamp, not a source-data or registry instant.

`process.py:3408` visibly refuses every present backtest payload `as_of` with unavailable-dependency/after-condition before receiver acceptance and QMB placement, because current transport cannot preserve it. This is an honest unsupported-path refusal, not successful optional-input support. It must remain until the whole path is implemented. Root's user-authorized full scope includes completing that path; permanently excluding the optional input would narrow the requested work.

`qmb/host/qma_cli.py` has a closed delegated payload and a revalidated nominal QmaBacktestContext without `as_of`; its gate rejects extra keys. `qma/daemon/backtest/cli.py` serializes that delegated payload/environment, has a closed preflight result parser, and launches actual children. `backtest/service.py:801-871` derives expected_result and persists the complete invocation/expected context as immutable CT-11, then links it to JobHandle. `backtest/expected.py` verifies physical canonical content/digest and expected-proof linkage. `qmb/host/operator_occurrence.py:506` currently fingerprints delegated context without a cut. Consequently an isolated process-gate removal, new environment variable, or unchecked result field would leave the boundary incomplete.

## Minimum complete implementation contract

1. In the public call helper/dispatcher, retain exact optional-input presence and complete InputHash. Parse a present value with the shared UTC-Z/Instant parser; malformed/null/bool values are typed invalid input unless the owning registered schema explicitly permits them. Compare the parsed supplied cut to the approved immutable ProductSession context. A stale or future different context is a typed mismatch; no silently refreshed context, borrowed session, or regenerated hash.
2. Preserve all existing authoritative checks: authenticated principal, opaque actor/actual Mission ownership, exact contribution/version/availability, operation/version/effect, selected instance/config revision, GrantRecord and context revision, permissions, target refs, current Task/outbox/dispatch lease and attempt, deployment, environment and occupancy. The cut bounds input knowledge; it does not select a historical grant, owner, lease, or retry state. Revalidate current authority after read-only child preflight and before receiver acceptance/effects.
3. Establish a shared typed **frontier validation** helper used before builder/evaluation and during verification for both Book and Alternative. It must reopen the pinned descriptor, actual registry set/record contents, CT-10 source and CT-12 split/role/world, rather than trust echoed strings. For historical input reads, require the actual relevant facts to satisfy their owner-defined knowledge-time bound and registry set instant/availability to be valid at the cut. Reject unsupported/missing knowledge metadata or a descriptor/ref/source inconsistent with the cut. Do not truncate a pinned source and then keep its old source/result fingerprint. Any legal newly selected dataset/config must have its own correct identity.
4. Carry the approved cut plus a durable binding to the full validated public input/authority context through existing CT-47 construction, `backtest/cli.py` child payload, `qmb/host/qma_cli.py` exact decoder/revalidator, and closed preflight response. The representation must distinguish optional input omission from presence; absent public input need not imply absent approved session context. No mandatory new public operation or undocumented wire field is required: extend the versioned owner contracts consistently. If duplicated environment fields are used, clear inherited copies and require exact agreement.
5. In `backtest/service.py` expected_result/CT-11 expected-context and actual JobHandle restart reconstruction, pin the same cut and complete authority/input binding, exact descriptor, registry/source/split/role/world refs, composition/result class, job and attempt. Carry identical data into Book and Alternative actual producer result/terminal claim and private CT-13 witness identity. Source/config computational identity and delegated occurrence authority are separate; do not arbitrarily put a session wall time into Book/PolicyPair identity.
6. Verification must reopen producer evidence and underlying selected refs and compare the **whole** expected binding. Claimed and claimless verification must require the exact current producer witness; no aliasing another job/attempt/result or accepting an echoed cut as proof. Restored expected artifacts must preserve the binding without relying on mutable current ProductSession, process environment, descriptor latest, or current wall clock. A later output-recorded-at is legitimate: preserve actual output occurrence time and the input cut separately.
7. Unsupported or unprovable frontiers return typed refusals before receiver acceptance, occupancy/job placement, materialization/builder, evaluation, or domain evidence effects; read-only preflight is permitted. Existing partial/cancel/UNKNOWN semantics remain; no completion from exit code/progress or a preflight echo alone. Implement the same deep contract on each supported door, preserving ordinary headless parity.

The supported minimum is a matching explicit approved cut with immutable inputs proven valid at that cut, not a new arbitrary historical-query engine. Matching does **not** mean cut equals registry instant, CT-12 boundary, or final event instant. A cut later than the selected data frontier can be valid. A cut earlier than an input's relevant knowability cannot authorize that same unmodified pinned run. Future relative to the approved context, stale different context, missing proof, or mismatched refs must refuse. A legitimate historical context may require a separately approved/rebound context and matching inputs; no blanket refusal of all historical requests is implied.

## Required finite acceptance cases (not executed here)

An omitted optional input remains the legitimate existing path with distinct InputHash.
- Event time before cut but known-at after cut refuses; registry selected set later than cut refuses; same timestamp with foreign set/source/split/role/calendar/world refuses; malformed or missing required knowledge metadata refuses. Split no-peek and embargo controls remain independent.

- Durable close/reopen keeps exact explicit presence/cut/full input/authority binding. Source and witness readback disagreeing with expected cut or source refs refuses, with and without a terminal claim. Newly produced evidence recorded after the cut is accepted when its actual source inputs were valid at the cut; it is never backdated.
- Operation-specific projection uses the cited CT-32 occurrence/registry-as-of law, never caller query time. No test may manufacture a CT-12 boundary or source knowledge field merely to make the cut match.

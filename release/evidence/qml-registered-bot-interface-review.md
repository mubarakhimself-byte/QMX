## Existing exact API and join

1. Retain actual source tree bytes. `qml.logic.normalize_source_manifest` and `fingerprint_source_manifest` give the existing canonical source basis; `LogicIdentity.try_create(distribution, version, source_tree=...)` / `mint_logic_identity` joins them into distribution/version/source_manifest. LogicIdentity is an identity reference, not source storage. Save/read the selected complete source tree independently, then recompute its official manifest fingerprint; do not treat echoing a stored digest or loading an unrelated test callback as source readback.
2. Build official QML family, CT-34 confluence(s), producer bindings, footprint, parameter space and `mint_bot_definition` with that LogicIdentity. Use `lint_declaration(declaration, family_catalog=..., confluence_catalog=..., producer_catalog=..., formula_catalog=..., logic_catalog=...)` against the actual matching catalogs. These records/references must be resolvable for the same Bot, not replaced by a generic passing verdict. Producer/footprint transitive union and canonical assignment remain required.
3. Use `qmb.host.runner.run_sandbox(declaration=..., source_tree=..., factory_spec=None, assignment=..., state_scope=..., state_bound=..., timeout_seconds=...)`. The default path selects exactly one conventional `factory.py:factory` from the manifest and reconstructs it in the actual child. Explicit source FactorySpec must use those same matching bytes/entrypoint; silent fixture is refused for a production Layer-2 verdict. No callable-selector field is currently in LogicIdentity: do not invent a selector or use a different factory within the same tree to claim the assessed artifact.
4. `qml.conformance.collect_layer2_observations/run_layer2_suite` separately accepts both source_tree and caller factory; it checks tree manifest against the declaration, but that alone does not prove the independently passed factory came from those bytes. For the new registered journey, use the actual host source loader/sandbox. QML remains pure; host proof supplies this loader relationship. Existing `replay_request.resolve_replay_request:367-399` is the concrete source-bound model: sandbox matching tree, identify unique factory.py, `load_factory(FactorySpec(FACTORY_KIND_SOURCE, actual_text, module:factory), source_tree=full_tree)`, then construct from that factory.
5. `gate_registration(layer1=..., layer2=...)` returns `RegistrationCandidate` only when their declaration fingerprints match. Candidate retains declaration, logic, semantic fingerprint, both full verdicts and ticket. Before stamping, recompute the candidate declaration/logic/source relationship and match it to the actual declaration selected for registration. Keep both verdicts and golden-slice identity as evidence of what was assessed; a boolean ticket is only the reduced host summary.
6. QMB composition root `install_bot_domain_kinds(KindRegistry())` installs official confluence/Bot/family kinds. `register_strategy_family`, `register_confluence` and `register_bot_definition(declaration, registrar=Registrar(...), writer=..., sequence=..., created_at=..., ticket=candidate.ticket, at_birth_parent_refs=...)` use the existing CT-06 Registrar. Preserve QML authored body/parents and real root WriterId/Instant/strict per-writer sequence. Do not add source or conformance fields to public CT-33/CT-06 schemas. `mint_generation_envelope` is the QMB host wrapper for AuthoredStructure, not a durable persistence primitive.
7. Registrar is explicitly an in-memory reference admission guard. Actual durable registration requires `RegistryPersistence.open(EvidenceStore(root), world)`, `persist_record(receipt.record)`, close and fresh open, then `load_record(receipt.record.stable_id, for_world=world)`. Check exact kind/envelope version/kind version/parents/body/stable storage identity. Rebuild official CT-33 from the actual reopened body and parents, reconstruct its LogicIdentity, and join it to freshly read source bytes before loading the recovery factory. Reopen CT-34 and family records too; verify their canonical semantic fingerprints match the Bot's actual cited references. A Registrar receipt alone proves no physical persistence.

**Identity precision:** `BotDefinition.fingerprint_content` hashes its semantic identity payload (kind, kind-format, six-group body, optional parents). `RegistrationRecord.stable_id` hashes its CT-06 canonical envelope, with additional class/envelope format and at-birth parent field. These implemented canonical shapes differ; do not assume the two fingerprints are identical. Retain the CT-06 storage key→actual body→reconstructed semantic Bot fingerprint relationship. QML state scope and candidate use the semantic Bot fingerprint; physical persistence uses the receipt record key. The same distinction applies when resolving a CT-34 semantic cite against its actual stored envelope. If another downstream owner requires a different identifier mapping, use its official constructor/adapter explicitly; do not silently swap identities or invent equivalence to make a test pass.

## Ticket limitation and minimum host binding

`ConformanceTicket` carries only `layer1_passed` and `layer2_passed`. `register_bot_definition` tests a ticket and both truth values, then independently accepts the declaration; it does not accept/reconstruct RegistrationCandidate, compare verdict/declaration/source fingerprints, or check the actual factory origin. Its trusted-host API therefore relies on the caller to maintain that join. A passing ticket by itself is **insufficient independent evidence that this particular artifact passed**. This is an ordinary missing content-binding guarantee, not a claim of malicious forging or a security review. Existing `test_bot_registration.py` uses `evaluate_ticket(True, True)` and a recording Registrar to prove stamping ownership/no-ticket refusal; it neither performs source-bound conformance nor durable registration.

The new journey can prove the genuine supported positive by retaining the exact gate candidate, stamping its same declaration/ticket, saving its actual source and physically reopening everything. It must not label a plain bool-only call as an identity-bound registered pathway. A shared trusted host registration adapter should preflight the complete candidate/declaration/source/logic join before any Registrar or persistence effect and expose a typed refusal for a mismatched candidate. Passing Candidate A's ticket to declaration B directly is not currently refused by this API's structure; do not write a green test pretending otherwise. If test scope includes that host refusal, the implementation gap needs a separate authorized bounded product repair/freeze, not only a test-local assertion. Python nominal dataclasses are trusted values; no cryptographic/nonforgeability property is implied.

Cross-Bot, cross-OS/assignment/world scope refuses **before factory construction**, with real effect counters. Source distinction alone is not a substitute for these tuple guards.
- A differing second-run or other ordinary conformance failure refuses before stamping/persistence, with unchanged evidence bytes/no Registrar calls; unrelated callback, foreign source/manifest, wrong candidate/declaration/logic pair, wrong factory bytes/entrypoint or missing actual catalogs cannot be called a passing registered proof.
- Persisted-record/ref/body/parents/logic and source readback mismatch refuses before reconstruction effects. No current pointer/latest lookup, rewritten version or new default source is permitted. Explicitly distinguish CT-06 storage key and semantic identity in assertions.

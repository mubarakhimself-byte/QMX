## Read this first: the five-hour reading gates every Background plan send

A Background plan send needs a five-hour reading in the usage ledger, or `BackgroundCap` refuses it with "there is no reading of the plan's five-hour window yet". Two facts make that a risk for unattended runs.

1. `Harness.meter()` gives no five-hour reading on today's CLI. Its `/usage` reply now lists only "what's contributing to your limits usage" (requests, sessions, parallel share, subagents) and no session percent. HP0 S10 saw a session percent. The first `p_background` run on the ship home was refused for this reason before any CLI started.
2. A reading leaves the ledger once its reset passes (`p_limits`, 2 s case). After each five-hour reset, every Background plan send refuses until something writes a new reading. Only a plan turn's rate-limit event does that today, and a Background chat cannot run the turn that would write it. An Interactive plan turn does, and the probes seed the reading with one such haiku turn when the ledger has none (`common.plan_harness`).

EP10 and EP11 must not map this refusal to `waiting(limit, resume_at)` with the reset time, because no reset is coming that lifts it. The engine needs a way to get a reading on its own, for example an Interactive-kind meter turn or a harness meter that reads the five-hour window from somewhere other than `/usage`. That likely needs a harness request.

## Perf (not gated, for L6)

Mode B is the baseline. Each slowdown is mode A wall time over mode B wall time, minus one. By task: 01 +113%, 02 -39%, 03 +19%, 04 +5%, 05 -21%, 06 -18%, 07 +9%, 08 -45%, 09 +28%, 10 +12%. The median is +7% and the totals differ by +2%. One task, 01 at 6.8 s versus 14.5 s, crossed the 50% risk line. In the one-task smoke run before the full set, the same task took 19.6 s in mode B and 18.1 s in mode A. Each mode ran each task once, and haiku turn latency varies from run to run, so this is noise and not a risk for L6. The scratch-folder backend adds no container start. A Docker backend would add one `docker run` per attempt, and that cost is not measured.

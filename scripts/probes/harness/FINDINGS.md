## Design facts these runs disprove

1. **`reconnect_mcp_server("qmx")` does not re-list an in-process server.** AD-61 and H47 name it as the path until the SDK forwards `tools/list_changed`. On CLI 2.1.299 the call raises `SDK servers should be handled in print.ts`, and the CLI never asks the server for its list again. The SDK bridge drops the `tools/list_changed` notification, as the spine already said. P-PK fails both ways, so P-TG ran.
2. **`toggle_mcp_server` switch-offs do not leak, and they hold during connect.** AD-61 rules toggling out because "the CLI keeps a switch-off in its own state for the workspace and a switch-off sent during connect does not hold" (measured S35 on an earlier CLI). On CLI 2.1.299 a switch-off sent right after connect held. A switch-off in one chat did not reach a second chat on the same workspace or a resumed chat. 40 in-process servers settled in 0.72 s. P-TG passes.
3. **An undeclared Bash does not always reach the named policy.** P-PERM expects it to. The CLI runs a read-only Bash command (`echo`) without calling `can_use_tool`. It also runs a Bash write into a folder that an `Edit(...)` allow rule covers without calling it. A Bash write outside every allow rule does reach the policy. The other seven P-PERM cases pass.
4. **The 64-character tool name is not the plan API's limit.** AD-61 checks that `mcp__qmx__<name>` is at most 64 characters. On the plan lane, 65- and 80-character names loaded, went on the wire unchanged (read from the fake model), and answered. The CLI rewrites a dot in a tool name to an underscore, and the call still reaches the dotted name on the server. Other providers were not tested.

## Other facts the runs recorded

- On Windows the CLI never matched a `Write(<path>)` permission rule or the `//D:/...` form. `Edit(//d/<path>/**)` (lower-case drive, no colon) and a cwd-relative `Edit(./**)` did match, and an `Edit` rule also covers Write. These come from fake-model reads during development; the P-PERM run uses the `//d/` form.
- The Agent tool on CLI 2.1.299 launches a sub-agent in the background ("Async agent launched"). Its reply arrives as a `task_notification` whose `summary` holds the agent's final text. The output file the notice names was gone by the time the probe read it.
- haiku refuses to repeat its system text when asked for a codeword in it. The P-SYS checks therefore ask it to follow a rule in the append, never to reveal the append.

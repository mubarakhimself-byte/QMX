# Answers to the engine's LIBRARY-REQUESTS L1-L17

Read against `architecture/workflow-engine/LIBRARY-REQUESTS.md` and the engine spine's AD-14, AD-18, AD-20, AD-23, AD-25, AD-26, AD-27 on 2026-10-16 (night). Every request is granted; three are granted in a different shape than asked, with the reason and the exact form the engine should code against. L11-L14 were left unanswered by the first pass (wayfinder gap 5) and are answered below, together with L15-L17 from the gap-fix pass of ruling 88 (27b B3, B4, S7); L9 is reworded.

## Mismatches the engine architect should fold

1. ~~Engine AD-14 names kinds `workflow_version` and `test_report` as separate kinds.~~ **Folded (27c):** engine AD-14 now uses the Library names: a version is an object of the `workflow` item, `(item_id, semver annotation, object_id)`; "tested" keys on `fields.content_hash` and `publish` copies `tested-by` when the hashes match (27d C1); `test-report`; `workflow-run`.
2. Engine AD-14's edge set is covered and now uses the hyphenated names; `consumed_by` reads as the reverse of `consumed`; `archived-as` is an at-birth relation on the replacement object plus the item-state entry; the engine's `supersedes` is `replaces` (27c).
3. Engine AD-26 "`main` moves only by his click" is kept **for challengers only** (AD-18); every other workflow output fast-forwards under the workflow's `publish` rule, except run-made lifecycle kinds, which land as drafts (L15).
4. Engine AD-18's scope caps and snapshot rendering are engine behaviour; the Library only stores rows and serves `search_runs`/`find_by_intent`.
5. The word "hub": say "the Library Hub" (`qmx_hub`) and "the node inbox" (DEC-0188).

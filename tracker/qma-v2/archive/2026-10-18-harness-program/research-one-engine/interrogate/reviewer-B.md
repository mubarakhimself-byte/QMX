# Interrogate, reviewer B: QMA v2 one-engine synthesized design

Reviewed: `architect/DESIGN.md`, `architect/SYNTHESIS.md`, every file under `architect/sketch/qma/`. Checked against `01-requirements.md`, `02a`, `02b`, `03-gaps.md`, `04-baseline.md`, `how/HOW-one-engine.md`, the candidate designs, and the code at `D:/QMX-worktrees/harness-survey`. One SDK fact was checked against the primary source (`claude_agent_sdk/types.py` on GitHub main): `ClaudeAgentOptions.settings` exists ("Path to an additional settings JSON file to load, or an inline JSON string"), and `SystemInitData` is emitted "at the start of each turn".

Severity counts: 2 critical, 16 warning, 5 nit.

## Findings

### 1. [critical] The plan token sits in a file the agent can read, and nothing denies or measures that read
**Location**: `sketch/qma/harness/money.py` `GateRules.protected_paths`, `gate`, `deny_rules`, `run_exposure_probe`. `DESIGN.md` §3 "The exposure probe" and §5 S21, S26.
**Finding**: On Windows and Linux the CLI stores the plan login in `<CLAUDE_CONFIG_DIR>/.credentials.json` (02a §14: "all move under `CLAUDE_CONFIG_DIR`"). That is `<qmx_home>/claude/.credentials.json`, and his personal `~/.claude/.credentials.json` holds the same plan. The gate denies only Write, Edit and NotebookEdit into protected paths, plus Bash text that names a protected path literally. Nothing denies `Read`, `Grep` or `Glob` on either credentials file. The Bash tripwire is bypassed in three easy ways. The agent's env carries `CLAUDE_CONFIG_DIR`, so `cat "$CLAUDE_CONFIG_DIR/.credentials.json"` names no protected path. The default workspace is `<qmx_home>/workspaces/<x>` (`harness.NewChat.workspace`), so `../../claude/.credentials.json` is a relative path. And string concatenation works in Python.
Once the agent has read it, the token is in the transcript. In a Kimi or GPT chat that transcript goes through the relay, which is a QMX process, to a third party. `translate.py` would parse it for GPT. In a plan chat it can go out through `mcp__qmx__delegate(profile="kimi", prompt=...)`, which is `DOMAIN_WRITE` and so can run without an ask, or through WebFetch or curl.
**Evidence**: 01 §7 requirement 1 says QMX "never holds or passes" the token. 02b A lists relaying it as "clearly barred". The design avoids the token only on the request path. It never treats the token as data at rest that an agent can reach. Worse, the exposure probe is told never to touch it ("It never opens a `.credentials.json`"), so the usage page cannot show this exposure. S21 greps QMX files and the echo server's *headers*, never request bodies, and no agent tries the read, so S21 passes while the invariant is broken. Candidate 3's Z1 check covered exactly this file ("his `~/.claude/.credentials.json`"). The synthesis dropped the zone and nothing replaced that coverage.
**Suggestion**: Add both credentials files (and `~/.claude.json`) to a new `secret_paths` set: deny rules `Read(//…)`, `Grep`, `Glob`, `Edit`, `Write` in `disallowed_tools`; a gate rule that denies Bash or PowerShell text containing `.credentials.json` or `CLAUDE_CONFIG_DIR`; and a relay check that refuses any body containing `sk-ant-o`. The relay check is cheap and is the only one that is structural for key and GPT chats. Have the exposure probe record whether the file is *readable* (`os.access`, never opened), and show it on the usage page as a "plan token posture" next to the money posture. Extend S21: in bypass mode and inside a sub-agent, the agent tries to Read and `cat` the canary file, then delegates to an echo-server profile. Pass means no canary in any relayed body.

### 2. [critical] Live-chat capacity has no defined behaviour when full, and unattended asks pin slots forever
**Location**: `sketch/qma/harness/harness.py` `Harness.send` ("evict the least recently used idle chat") and `_delegate`; `chat.py` `idle_seconds` and `_can_use_tool` ("The wait has no timeout"); `DESIGN.md` call site 3 and §3 Tradeoffs ("PreToolUse `defer` ... later").
**Finding**: Eviction only removes *idle* chats. A chat with a pending ask reports `idle_seconds == 0`, so it is never reaped or evicted. A Background chat in `default` mode that reaches its first Bash call at 3 a.m. parks a future with no timeout and holds a 170 to 610 MB CLI until the operator answers. Four such chats (the default `max_live_chats`) mean no new chat can start, the operator's Interactive chats included. Nothing says what `send` does at the cap with no idle chat: refuse, queue or exceed. `_delegate` makes it worse. The parent is mid-tool-call, so it is never idle, and the child "counts toward `max_live_chats`". With the cap full, a delegating chat either fails or waits on capacity that only it can free.
**Evidence**: R6 and call site 3 make background chats a core scenario, and 01 §9 Q4 leaves open whether they ask at all. 02a §4 names the native fix: PreToolUse `defer` ends the turn with `tool_deferred`, so "the process can exit and resume". The design keeps that for "later" and adopts the failure mode now.
**Suggestion**: Background and Child chats return `defer` from the PreToolUse adapter for any call that would ask, then close. Answering resumes the chat. That frees the slot and survives restarts, so "pending approval expires on restart" goes away for those kinds. Define the at-cap rule explicitly. Prefer refusing with a `needs_you` block over queuing. Give `delegate` a reserved slot or a refusal, never a wait. Add a check: cap 2, two Background chats blocked on asks, then start an Interactive chat.

### 3. [warning] `settings.json` stays agent-writable and live, and a two-path user tier is built on it; the SDK's `settings` option removes both problems
**Location**: `sketch/qma/harness/home.py` `FORBIDDEN_SETTINGS`, `load_user_settings`, `UserTier`, `probe_user_tier`, `UserSettings.permission_rules`; `launch.py` `build_options` (`setting_sources=["user"] if ISOLATED else []`); `DESIGN.md` §3 "Isolation, both directions".
**Finding**: The design loads `<qmx_home>/claude/settings.json` through the `user` source and treats it as hostile ("parsed at every launch"). It has four gaps.
(a) The validator runs only at launch. The CLI watches its settings files mid-session (Claude Code has a `ConfigChange` hook event, 02a §3), so an edit made by agent Bash, for example with the `$CLAUDE_CONFIG_DIR` bypass in finding 1, can change live permission rules or hooks before any launch check runs.
(b) The refusal list is a hand-kept blocklist. `env.HTTPS_PROXY` plus `env.NODE_EXTRA_CA_CERTS` passes it, and that routes plan traffic and its bearer through a proxy the agent chose. The same holds for `env.ANTHROPIC_VERTEX_BASE_URL` and other prefix names that are not in `ROUTING_KEYS`.
(c) The `LEAKS` fallback is lossy. `permission_rules` returns only `(allow, deny)`, so ask rules are dropped. `env` knobs are not carried at all, including `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, which is how the design enforces R33, and `cleanupPeriodDays`.
(d) Two code paths (`ISOLATED` and `LEAKS`) plus a per-CLI-version probe exist only to decide how the same rules reach the CLI.
**Evidence**: `ClaudeAgentOptions.settings: str | None`, "an additional settings JSON file to load, or an inline JSON string" (types.py, verified). Flag settings sit above user settings in precedence.
**Suggestion**: Code judo. Keep QMX's Claude-native settings in a QMX-owned store, written only by `write_user_settings`. At each launch, pass the validated JSON inline via `settings=` with `setting_sources=[]`. Validate with an allow-list of keys and `env` names, not a blocklist. QMX skills, agents, commands and hooks already ride in the plugin, and CLAUDE.md can ride in `append`. Then the on-disk file the agent can reach has no power. `UserTier`, `probe_user_tier`, the `LEAKS` branch and `FORBIDDEN_SETTINGS` all go, and the depth limit applies on every path. Keep S7 only to prove that his `~/.claude` stays out.

### 4. [warning] Native sub-agents can call `delegate`, so sub-agents spawn full sub-chats (R33)
**Location**: `sketch/qma/harness/tools.py` `tool_defs` (delegate added for every non-Child chat), `Effect.DOMAIN_WRITE` docstring; `launch.py` `Child` docstring; `DESIGN.md` §3 "No re-implemented sub-agent limits".
**Finding**: Only Child chats lose `delegate`. A native sub-agent inside an Interactive or Background chat gets every MCP tool by default (02a §5: "Omitting `tools` gives the agent every tool"). So it can call `mcp__qmx__delegate` and start a new CLI process on another provider. That is a sub-agent starting a sub-agent, and it bypasses `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`. With `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` at its default of 20, a fan-out can ask for 20 child CLIs at once (see finding 2). Also, `delegate` is `DOMAIN_WRITE`, which may be set to "allow", so a model can send arbitrary workspace content to a third-party host without any ask.
**Evidence**: The operator corrected this four times (01 §5, C17, R33: "Sub-agents never spawn sub-agents. Enforce it in settings"). Hook input carries `agent_id` inside sub-agents (02a §3).
**Suggestion**: In `gate`, deny `mcp__qmx__delegate` when the hook input has an `agent_id`. Make `delegate` its own always-ask effect, or at least ask when the target profile is not first party. Add an S11 case where a sub-agent tries `delegate`.

### 5. [warning] The 50% background cap (R6) cannot fire at 50% as designed, its backstop conflicts with verbatim chats, and overage spend is unguarded
**Location**: `sketch/qma/harness/usage.py` `BackgroundCap.allows` ("Unknown utilization allows"); `chat.py` `send` and `_read` (`on_plan_limits`); `project.py` `Limits.window` includes `"overage"`; `DESIGN.md` §3 "Usage and the background cap", S10.
**Finding**: `RateLimitEvent` fires only on status transitions (02b F item 2). A long-lived background CLI gets no new utilization reading between its first response and the `allowed_warning` transition, wherever Anthropic sets that threshold. So the cap acts at the warning threshold or at rejection, not at 50%. That is more than "can overshoot". The proposed backstop, sending `/usage` (S10), cannot run in Background chats, because they are `verbatim_prompts=True` and slash dispatch is off by design. Separately, `Limits` models an `overage` window, but nothing stops a chat that has moved into paid extra usage. If his account has extra usage on, plan turns past the limit cost money, against hard rule 1 ("No Claude or OpenAI API spend, ever").
**Evidence**: R6 ("50%, but editable") is one of his explicit numbers. 03 GB-9 already called it best effort. The design does not tell him that 50% is not what he gets.
**Suggestion**: State plainly on the usage page and in the plan for the operator that the cap triggers on the last reading. Recycle Background CLIs per job so each job starts with a fresh reading. Treat any `overage` status, or `credits_required` in `raw`, as a hard stop for all chats. Add a `doctor` line for whether extra usage is enabled. If `/usage` proves usable (S10), run it from a dedicated non-verbatim meter path, not from Background chats.

### 6. [warning] The money posture fails open: a credential the probe could not reach counts as safe
**Location**: `sketch/qma/harness/money.py` `money_posture` ("every broker credential in `broker_refs` that `exposure` found reachable has `scope_proofs[ref] is True`"), `run_exposure_probe`, `exposure_targets`.
**Finding**: STRUCTURAL needs scope proofs only for credentials the probe *found reachable*. The probe tries one method, `python -I` with the `keyring` package, against names listed in `settings.toml`. The agent has many more: PowerShell P/Invoke `CredRead`, `cmdkey`, `security find-generic-password` on macOS, `secret-tool` on Linux, or a file vault like QMN's chmod-600 `/etc/qmx/vault` (`qmx_control/node.py` `read_secret`) if the node shares the PC (R25). A keyring backend mismatch under `-I`, a macOS ACL that blocks `python` but not `security`, or a credential the settings file does not name all yield "unreachable", and then STRUCTURAL is shown.
**Evidence**: The posture is the design's main honesty device (§3 "Accepted tradeoff"). A false STRUCTURAL is worse than having no posture at all.
**Suggestion**: Drop reachability from the formula. STRUCTURAL holds only when every broker credential QMX knows about, from `settings.toml [brokers]` and QMN's config, has an S27 scope proof. Keep the probe as an informational list. That is simpler and fails closed.

### 7. [warning] The Bash tripwire is case-sensitive or over-broad, depending on how it is built, and either choice hurts on Windows
**Location**: `sketch/qma/harness/money.py` `gate` ("Bash/PowerShell text naming `qmx/`, a broker host or a protected path -> Deny").
**Finding**: The spec does not say how matching works. Windows Credential Manager target names are case-insensitive, so `keyring.get_password('QMX/ctrader', …)` slips past a case-sensitive match. A case-insensitive match on `qmx/` denies every Bash command that touches his own repo at `C:\Users\Mubarak\Desktop\QMX\…` (`/c/Users/Mubarak/Desktop/QMX/...`). That breaks "talk to it like Claude Code" on the repo he works in most. Relative paths and `$CLAUDE_CONFIG_DIR` defeat protected-path matching either way (finding 1).
**Evidence**: The design calls this "a tripwire, not a proof", which is fair. But a tripwire that fires on the operator's daily repo will be turned off.
**Suggestion**: Match keyring names case-insensitively on the exact `qmx/<name>` entries from `exposure_targets`, not on the `qmx/` prefix. Match protected paths after resolving them against the command's cwd and the env. Add an S6 negative case: ordinary Bash in his QMX repo is not denied.

### 8. [warning] Nothing stops a QMX agent from editing his personal `~/.claude`
**Location**: `sketch/qma/harness/money.py` `GateRules.protected_paths` ("The QMX home: …"); `deny_rules`; `DESIGN.md` §3 "Isolation, both directions" ("Nothing QMA writes is under `~/.claude`").
**Finding**: The isolation recipe stops the *CLI* from loading or writing `~/.claude`. It does not stop the *agent*. Write, Edit and Bash into `~/.claude/settings.json`, `~/.claude/hooks`, `~/.claude/skills` and `~/.claude.json` are all allowed. A QMX agent, possibly on Kimi and possibly prompt-injected by news, can plant a hook that runs in every one of his personal Claude Code sessions. The exposure probe records write rights to `~/.claude` but denies nothing.
**Evidence**: Hard rule 4 and R20: "QMX should be not interrupted by claude on my machine, and vice versa".
**Suggestion**: Add `~/.claude` and `~/.claude.json` to the protected paths (write deny) and to the `secret_paths` of finding 1 (read deny for the credentials). Extend S7: an agent in bypass mode tries to Edit `~/.claude/settings.json`.

### 9. [warning] The checks test layers only together, and several pass while their invariant is broken
**Location**: `DESIGN.md` §5 S3, S6, S7, S11; §3 boot ("Neither layer alone has to be right").
**Finding**:
- S6 checks the union of the hook and the deny rules. If the `Edit(//<path>/**)` rules are rendered wrongly on Windows (rule syntax is `//c/Users/...`, not `C:\...`), the hook still denies and S6 stays green. The dead layer goes unnoticed.
- S11 expects a Child's init list to lack `Agent`, but the init list names that tool `Task` (02a §5). The check passes even if the tool is present.
- S3 expects "Equal except Workflow". But `CONSTANT_ENV` turns on `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` (no feature-flag fetches, 02a §15). So either S3 fails on TodoWrite and on flag-gated tools, or it was run with QMA's env and no longer compares against vanilla.
- S7 looks only for his *skill* names. If his `~/.claude/skills` is empty, or the leak is in agents, commands, CLAUDE.md, rules or output styles, S7 passes.
**Evidence**: The design's principle is "check the real thing". These checks check proxies.
**Suggestion**: Test each layer alone: run S6 once with the hook removed (deny rules only) and once with `disallowed_tools` empty (hook only). Assert on `Task` and `Agent`. Name the expected S3 diff exactly (Workflow, TodoWrite) and run vanilla without QMA's env. Run S7 with a throwaway `HOME`/`USERPROFILE` seeded with marker skills, agents, commands and a CLAUDE.md phrase. That is fully controlled and never reads his real files.

### 10. [warning] Money MCP servers cannot be switched off "before the first prompt" from the init message
**Location**: `sketch/qma/harness/chat.py` `_connect` ("On the init message: switch off money MCP servers") and `_read` (`SessionReady -> money.money_servers`); `money.py` `money_servers`; `DESIGN.md` §3 step 3 and money layer 4; S35.
**Finding**: `SystemInitData` is emitted "at the start of each turn" (types.py, verified), so the first init message arrives only after the first prompt has been sent. A money tool on an external server is visible to the model during turn 1. The PreToolUse name check still denies it, so this is defence in depth, but S35's pass condition ("Switched off before the first prompt") cannot hold as sequenced.
**Suggestion**: After `connect()` and before `query`, call `get_mcp_status()` or `get_server_info()` (02a §1 and §15 list both) and toggle from that. Keep the init check as a re-check on each turn.

### 11. [warning] The OS memory cap gives every chat the same fate, needs Linux setup the design does not mention, and finds the CLI's pid by a race
**Location**: `sketch/qma/harness/procs.py` (whole module), `chat.ChatDeps.connect_lock`; `DESIGN.md` §3 "Processes and memory", S30.
**Finding**:
(a) One job or cgroup holds every agent tree. One chat's heavy backtest in Bash exhausts the shared limit, and allocations then fail in *other* chats' CLIs, the operator's Interactive chat included. S30 checks only that qmx-control survives.
(b) On Linux, moving a pid into `qma-agents.slice` needs write access to `cgroup.procs` of the common ancestor cgroup. A qmx-control started from a terminal sits in a root-owned `session-N.scope`, so `adopt_tree` fails with EACCES unless qmx-control itself was started under a delegated scope (`systemd-run --user --scope -p Delegate=yes`). The design does not say so.
(c) `new_child_pid` diffs qmx-control's children under `connect_lock`. But `doctor` (exposure probe subprocess, `GET /api/doctor`) and the mini-app supervisor start children outside that lock, so "exactly one new child" can fail or adopt the wrong process. MCP stdio servers that the CLI starts between the snapshot and adoption can escape.
**Suggestion**: Make the `cli_path` launcher the primary design, not the fallback: a tiny launcher that joins the job or cgroup, then starts the CLI. There is no pid hunt and no lock. Give each chat its own nested job or child cgroup under a parent that carries the global limit, so one runaway kills only its own chat. Document the Linux delegated-scope start in `qmb` and check it in `doctor`.

### 12. [warning] The boot scrub drops a Windows knob the Bash tool needs, and misses variables that reroute plan traffic
**Location**: `sketch/qma/boot.py` `SCRUB_PREFIXES`; `launch.py` `ROUTING_KEYS`; `home.load_user_settings`.
**Finding**: Removing all of `CLAUDE_CODE_*` also removes `CLAUDE_CODE_GIT_BASH_PATH`, which Claude Code on Windows uses to find Git Bash when it is not in a default location. Nothing restores it: it is not in `CONSTANT_ENV` or `QUIRK_ENV_KEYS`, and `doctor` lists only names. Going the other way, `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE` and `NODE_TLS_REJECT_UNAUTHORIZED` are neither scrubbed nor in `ROUTING_KEYS`. An agent can persist them with `setx` (`HKCU\Environment`) or with a settings `env` entry. The next `qma.serve` or launch then sends the plan bearer through a proxy of the agent's choosing.
**Suggestion**: Carry `CLAUDE_CODE_GIT_BASH_PATH` forward explicitly (allow-list it in the scrub and pass it in `launch_env`), and make `doctor` check that Bash resolves. Add the proxy and TLS variables to `ROUTING_KEYS` and the scrub. Plan launches set them to "" unless the operator configured a proxy in QMX settings.

### 13. [warning] Setting `started=True` at init can brick a chat for good, and 30-day pruning breaks old chats
**Location**: `sketch/qma/harness/chat.py` `_connect` ("On the init message: … record `started=True`") and module doc ("a missing transcript is an error, not a fresh start"); `home.ChatRecord.started`; `DESIGN.md` S14.
**Finding**: If the CLI connects but the first user message never reaches the transcript (crash, `client.query` failure, a Background chat refused by the cap after connect, a relaunch before turn 1), the record says `started=True` with no JSONL. Every later send uses `resume=sid`, fails, and shows an error block forever. S14 even asserts that error. Separately, Claude Code prunes sessions older than `cleanupPeriodDays`, 30 by default (02a §2). The design names the knob but sets no default. A chat the operator returns to after a month cannot resume.
**Evidence**: 01 §7 requirement 10 ("Run long sessions that last days, survive restarts").
**Suggestion**: Set `started=True` on the first `ResultMessage`, or when the transcript file exists. When `started` is set but no transcript exists *and* no turn ever ended, relaunch with `session_id=` instead of erroring. Set `cleanupPeriodDays` high in the QMX settings, and add an S14 case with an aged transcript.

### 14. [warning] The relay is described as a key boundary, but agent Bash reaches the keys anyway
**Location**: `sketch/qma/harness/relay.py` module doc ("Provider keys never sit in a CLI env, a CLI's Bash or a transcript"); `profiles.py` `KeyProvider` docstring; `DESIGN.md` §3 "No provider key ever sits in a CLI env, a CLI's Bash, or a transcript" and Alternatives ("It exposes every provider key to agent Bash"); S23.
**Finding**: The keys live in the OS keyring under the same OS user, so agent Bash reads `qmx/kimi` directly. The design's own exposure probe would list it. An agent can also rewrite a provider row's `base_url` in `settings.toml` through Bash, which bypasses `AGENT_OPERATIONS` and the `settings_put` exclusion. Any https host passes `parse_profiles`, so the relay then sends the real key there. The same applies to `qmx/chatgpt`, the SIWC refresh token, which gives general GPT access. S23 greps env and transcripts only, so it passes.
**Evidence**: The design rejects "keys in the CLI env" largely on this exposure argument. The real gains of the relay are wire quirks, authoritative usage, the family guard and a single home for the GPT lane.
**Suggestion**: Restate the relay's value without the boundary claim. Put provider keys and `qmx/chatgpt` in the posture list on the usage page. Re-parse and re-validate `settings.toml [providers]` at grant time, and pin each provider's host to a known list per vendor, or show a confirm in the UI when a base URL changes.

### 15. [warning] The family guard rejects valid requests, and `openrouter/auto` lets paid Claude or GPT through
**Location**: `sketch/qma/harness/relay.py` `guard_model` ("`model` must be one of the profile's tier models"); `profiles.py` `FORBIDDEN_ON_KEY`, `parse_profiles`.
**Finding**: (a) Vendor recipes use `[1m]` model suffixes (`kimi-k3[1m]`, `glm-5.3[1m]`, 02b B). If the CLI strips the suffix before sending, which is how it treats `[1m]` for Claude ids, an exact match against the tier map refuses every request with 400. (b) A tier set to `openrouter/auto`, or another router or preset slug, contains no forbidden fragment, yet OpenRouter may route it to Anthropic or OpenAI models. That is paid Claude or GPT API use behind a key, against R4 and hard rule 1.
**Suggestion**: Normalise `[1m]` and similar suffixes on both sides before comparing. Refuse OpenRouter router and preset slugs (`openrouter/*`, `@preset/*`) in `parse_profiles`. If available, have the relay read the upstream model actually served from the response (`message_start.message.model`) and log or refuse family hits.

### 16. [warning] The exposure probe will pop up Keychain prompts on macOS and runs on every `/api/doctor` GET
**Location**: `sketch/qma/harness/money.py` `run_exposure_probe`; `routes.py` (`GET /api/doctor` "runs the exposure probe"); `harness.Harness.doctor`.
**Finding**: On macOS, Keychain items carry per-app ACLs. A fresh `python -I` asking for every `qmx/*` item triggers one GUI prompt per item. If the operator clicks "Always Allow", agent Python then has silent access, so the measurement itself widens the exposure. Running it from a GET route repeats the prompts on every page load. Headless Linux Secret Service may also block on unlock.
**Suggestion**: Run the probe only on explicit request (POST) and once per CLI version. On macOS, check the item ACL with `security` (no secret read) instead of `get_password`, and state in `doctor` that the result is ACL-based.

### 17. [warning] SIWC background consent is stored but never enforced
**Location**: `sketch/qma/gpt/siwc.py` `SiwcSession.background_consent`; `relay.py` `Relay.grant(session_id, profile)`; `harness._delegate`.
**Finding**: OpenAI's terms require express consent for background use (02b D item 9). `Relay.grant` does not know the chat kind, and no other code reads `background_consent`. So a Background chat on the GPT profile, or a Child delegated from one, runs on his ChatGPT plan without the consent the terms require.
**Suggestion**: Pass `ChatKind` into `grant`. Refuse a GPT grant for `Background`, or for a `Child` whose root chat is Background, unless consent is stored. Add an S16 case.

### 18. [warning] Several defaults quietly depart from vanilla Claude Code in a real repo
**Location**: `sketch/qma/harness/launch.py` `CONSTANT_ENV`, `workspace_instructions`, `build_options` (`project` source off); `DESIGN.md` §3 Isolation.
**Finding**: His sign-off is to "talk to it like Claude Code" (R10), and the floor is vanilla (hard rule 7). In a repo workspace such as his QMX repo, QMA does not load `.claude/skills`, `.claude/commands`, `.claude/agents`, `.mcp.json`, CLAUDE.md files in subfolders, or parent-folder CLAUDE.md. It reads the root CLAUDE.md once into `append`, which is snapshotted until compaction (02a §2), while vanilla re-injects CLAUDE.md on every request. `DISABLE_NONESSENTIAL_TRAFFIC` turns off feature flags and `ENABLE_TODO_TOOLS` adds tools. None of this is listed under "Tradeoffs accepted", and S3 and S4 run in QMX's home, not in a repo, so they cannot see it.
**Suggestion**: List each deviation as an accepted tradeoff with its reason. Offer a per-workspace "trusted repo" switch that loads `project` skills, commands and agents (still not project `settings.json` or hooks). Run S3 and S4 once inside his QMX repo.

### 19. [nit] `OperatorText` means whoever holds the bearer, not the operator
**Location**: `sketch/qma/harness/routes.py` ("The turn route is the only producer of `OperatorText`"); `chat.py` `OperatorText`; `DESIGN.md` §3 "Prompt ... Who wrote the text is in the type".
**Finding**: Any holder of `qmx/control-token` can POST to `/api/sessions/{sid}/turns`. That includes agent Bash and mini-apps, whose manifests carry the token (HOW "Where the earlier explanation differs"). Such a caller can inject slash commands into an Interactive chat and answer its own asks, including MANAGE asks (R35). The tradeoff covers approvals, but the type-level claim is stronger than the mechanism, and S25 does not test the route.
**Suggestion**: Say "route-provenance, not author-provenance" in the docstring, and show this speed bump on the usage page next to the money posture.

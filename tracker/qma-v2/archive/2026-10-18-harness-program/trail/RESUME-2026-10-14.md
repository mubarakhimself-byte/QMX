## The ruling that changed everything (operator, 2026-10-13, night)

**One engine, the Claude Agent SDK. No OpenAI Agents SDK.** The operator's reasoning, which the planning session confirmed against the sources:
- Every provider except GPT speaks Anthropic's Messages format and is built to run inside Claude Code:
  - Claude on his Max plan;
  - Kimi, DeepSeek, GLM and MiniMax;
  - Meta Muse at `api.meta.ai/v1/messages` (H1 fact 19).
- "Sign in with ChatGPT" is not tied to any SDK. It yields a token that is sent to OpenAI's Responses endpoint, `api.openai.com/v1/responses`, in OpenAI's format.
  - It only ever gives GPT models.
  - Plan requests must use `store: false` and `stream: true`, carry no system-role message, and set no sampling fields. Hosted tools and computer use are unavailable.
  - Sources: H1 fact 17; help.openai.com article 20001542; workos.com/blog/sign-in-with-chatgpt-plan-usage-scope.
- So GPT needs only a small **translator** in QMX: Anthropic Messages in, OpenAI Responses out, with his ChatGPT token. It needs no second SDK. LiteLLM documents the API-key version of this (docs.litellm.ai/docs/tutorials/claude_non_anthropic_models). The plan-token version is UNPROVEN and must be probed first.
- OpenRouter's Anthropic endpoint is "only guaranteed to work with the Anthropic first-party provider" (H1 fact 20). Non-Claude models via OpenRouter may also need the translator. This is a probe item.
- This reverses his 2026-10-12 15:16 rejection of "other models on the Claude engine". He reversed it himself, so it is now settled.

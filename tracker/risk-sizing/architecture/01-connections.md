# 01. Every connection between the parts, inside QMX and outside it

Written 2026-10-31 by agent A0; amended the same evening by agent X0 after review R0 (`review/R0-level-0.md`; per-finding record in `level-0/R0-FIXES.md`). One writer at a time: the lead folds later changes in. This is the master every part's contracts must match: who calls whom, where it runs, the data that crosses (named shapes and their owner), the direction, the version rule, and what happens when the other side is down. The rules behind it are the Level 0 spine (`level-0/ARCHITECTURE-SPINE.md`, cited as AD-n); the words are the glossary's (`funnel/versions/GLOSSARY.md`). A Level 1 spine that needs a connection changed proposes the change in its own "Contract changes" section; this file's writer folds it in.

**Labels.** EXISTS = merged on `origin/engine/base` `c93407ca` (path given or cited through the grounding file that checked it). NEW = to be built. CHECKED = read or run this session; INFERRED = judgement.

## How to read this

**The one rule over every row (AD-2).** A unit trades with only what is on its own machine. No row below that crosses machines may be needed for a unit to trade; the only cross-machine link on the order path is the trading node's own link to its venue.

**Where.** `in-process` (one Python process); `same machine` (two processes on one machine: a host and an app, or two apps); `cross-machine` (over the network between his machines); `external` (to a broker, exchange, data vendor or time source).

**Version rules.**

| Code | Rule |
| --- | --- |
| V-S | the shape carries `schema_version`; fields addable, meanings never change; readers read every version they support (AD-6) |
| V-K | a Library kind's schema file with `schema_version`; stores open, upgrade after a copy, or refuse by name (Library AD-3, AD-35) |
| V-P | the call is pinned to `(app, version)`; the pin is revalidated per call and never resolves to another version silently (engine AD-64) |
| V-CT | a CT contract format version; a reader refuses a version it does not know (fail closed); CT-23 format 3 is the unit's sized intent (AD-18) |
| V-H | both sides state their contract versions on connect; on a mismatch the node keeps trading what it has and refuses new deployments until they match (AD-6) |
| V-L | a pinned library or protocol descriptor (`ccxt` 4.5.85, cTrader `openapi-91.pb`); the venue's capabilities are re-verified at every connect and after any upgrade (CT-18) |

**Down.** What happens when the other side is down, slow or unreachable.

## 3. Between machines (networking)

Machines: This PC (Windows; its host and its OpenObserve bind loopback only, `HO/host.py:254`, `HO/connect_logs.py:186-188`), any server (Linux, host bound to its Tailscale address only, `HO/host.py:254`), all on his tailnet.

**The direction rule (AD-44).** Every cross-machine link is opened by This PC, or ends on a server or outside QMX. Nothing connects into This PC: no row below has a server opening a connection to it.

**The routes, as they exist or as AD-46 adds them.** REST and MCP over streamable HTTP on the host's one port behind one bearer (`CTL/server.py`, G2 §6). The engine's forwarding route and its held stream per reachable owned node (`HO/streams.py`), which carry engine runs and inbox items only (`ENG/service/forward.py:50-63`, frames `inbox` and `keepalive` at `:360-369`); a dropped stream re-reads the open items every 5 s (`HO/streams.py:24`), with no event replay and no `Last-Event-ID`. Run passes on `POST /api/data/read`, the only route a run pass reaches (`HO/door.py:94`). The Library hub, which This PC calls with the pairing key (`HO/door.py:38-41`; Library AD-11, AD-14). **NEW, AD-46:** one host-pass route on every host, `POST /api/host/forward`, with a closed verb set (`apps.ask`, `apps.job`, `heartbeats`, `data.list`, `data.fetch`); today a host pass reaches only the two cTrader sign-in routes and the engine's two forwarding routes (`HO/door.py:166-179`, CHECKED by running `host_pass_call`, `level-0/blast-radius.md` item 10). OpenTelemetry goes to each machine's own collector (engine AD-69, as built).

## 7. Using this file

A Level 1 part checks each of its connections against a row here: the same shape name and owner, the same door, the same version rule, the same behaviour when the other side is down. A connection a part needs that is not here is proposed in that part's "Contract changes" section. A row here that a part cannot meet is a conflict to surface, never a local override.

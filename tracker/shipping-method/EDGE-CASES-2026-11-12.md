# Edge cases for the shipping method (12 November 2026)

Read: DRAFT, ROLES, PR-BODY-AND-SKILLS, ORCA-TRIAL and FABLE-CHALLENGE beside this file, and the old `PROMPT-ORCHESTRATOR.md` and `SPEED-REVIEW.md`. Assumes the current decisions: all roles are Opus 5.5 background agents in Claude Code desktop, the coordinator wakes when they finish, the laptop does the compute, there are no hard caps, every PR gets a deep review, and only his click moves the protected branches.

Left out because the lead already has them: files that contradict each other, a serial landing queue that takes 2 hours a slice, the vacuous fail-at-parent check on an ImportError, CI that can't run the suite and skips build branches, and the undefined planner handoff.

Ranked by harm. Each item gives the scenario, what goes wrong, and the smallest fix.

## The list

1. **A background agent writes in his main checkout.** Background agents start in the coordinator's folder, `C:/Users/Mubarak/Desktop/QMX`, and that folder is `main` with his uncommitted files. A builder that forgets to `cd`, or a fixer whose worktree is gone, edits and commits there. His work gets mixed with agent work, or lost on a reset. **Fix:** start the coordinator in an empty run folder, not the repo. Add a PreToolUse hook that refuses any Write, Edit or Bash `git commit` outside the agent's own worktree and its evidence folder. At every wake, a script compares `git status` of the main checkout with a snapshot taken at arm time, and stops the run on any change.

2. **His click is not enforced, because the agent token is his admin token.** Branch protection lets admins bypass it unless "Do not allow bypassing" is set. Agents use his `gh` login, so the protection that is meant to hold his click does nothing. **Fix:** turn on "do not allow bypassing" for `engine/base`, `integration` and `main`. In preflight, push a throwaway commit to a protected branch and require the push to be rejected. If the push succeeds, the run does not arm.

3. **A landing rebase changes behaviour, and the old review still counts.** Slice B is reviewed CLEAN on tip T1. Slice A lands and changes a function B calls, a constant B relies on, or a registry B adds to. B rebases with no textual conflict. Only B's own packages are retested, so A's packages, which B now affects, are not. B lands on a review of code that no longer exists. **Fix:** the landing script compares `git patch-id` of B before and after the rebase, and lists the files that the commits landed since B's dispatch touched. The review carries over only if the patch-id is the same and no file overlaps. Otherwise a fresh reviewer reads `git range-diff`. The slice checks after a rebase cover the union of B's packages and the packages of everything landed since.

4. **A half-written or stale file passes as proof.** The usage limit hits while a reviewer is writing. The file holds `CLEAN` on line one and nothing after it, and the script reads it as CLEAN. Or a fix-round builder dies early, and round one's `red.log` and `how.md` are still in `evidence/<id>/`, so the "three files exist" check passes. **Fix:** every evidence and verdict file must end with a line `END <head sha> <dispatch id>`. The scripts accept a file only when that line matches the current head and the current attempt. Keep evidence per attempt: `evidence/<id>/<attempt>/`.

5. **The builder says READY, but GitHub doesn't match.** It pushed nothing, pushed a different sha, left the last commit local, or opened the PR against `main`, because `gh pr create` defaults to the repo's default branch. The checks then run on a stale head, or a PR to `main` sits there for one wrong click. **Fix:** a `verify_ready` script, run before any check starts. It requires that `git ls-remote` equals the reported sha, that the sha descends from the recorded parent, that the diff is not empty, that the PR base is the build branch, and that the PR head equals the sha. Any mismatch counts as BLOCKED, not READY. The script opens the PR itself, with `--base` set explicitly.

6. **The brief is wrong about the code.** It names a function that has moved, gives a value the code no longer holds, or misses a caller. The builder can't edit the brief, and the coordinator can't change one mid-build. So the builder either builds to the wrong brief, writing a test that pins the wrong value, or quietly widens the scope. The reviewer judges against the brief and finds it met. Wrong code lands CLEAN. The clarity read ran at plan time, and slices that landed since may have moved the code. **Fix:** each brief lists its facts about the code, each with one command and its expected output. The script runs them at dispatch against the current tip, and the builder runs them again first. Any mismatch means `BLOCKED brief-mismatch <fact>`. The slice parks, with the fact in the report, and is never built around.

7. **The run report lies by omission.** An agent writes it from memory after a long run. It drops a FAIL line it judged to be "its own script error" (nine rows stacked that way last time), a skipped Linux check, a slice that landed with lows, or the hour the run sat idle. **Fix:** a script builds the report from `state.json` and `checks/`. It lists every slice with its final state, every FAIL line anywhere, every check not run, idle hours, and counts that add up to the total. The coordinator adds only a short "waits on you" section under it. "Landed" means `ls-remote` shows the build branch at or past the slice's sha.

8. **A hung agent never finishes, so the coordinator never wakes.** The coordinator wakes only when an agent finishes. A builder waiting on a permission prompt, a git credential popup, a rebase editor, or a test with no time limit never finishes. Nothing ticks, and the night is gone at 23:40. **Fix:** keep a heartbeat tick in the coordinator session as well (the `loop` skill, 600 seconds, as before). It checks each agent's last push and the mtime of its log. Preflight sets `GIT_TERMINAL_PROMPT=0`, `GIT_EDITOR=true`, `GCM_INTERACTIVE=never`, and an allowlist checked by a dry run, so no prompt can appear. Every test command goes through a wrapper that has a time limit and touches a heartbeat file.

9. **Old failures on the tip make every landing red.** If the build tip already fails some tests, every landing's full suite is red. Every slice parks, and the "three parks" breaker stops the run within the hour. **Fix:** keep a baseline file of known reds at the tip. Landing blocks only on new reds. A slice that fixes a baseline red removes it from the list, and the script rewrites the baseline after each landing.

10. **A usage limit or a crash counts as a failed attempt.** A builder killed by the usage limit, an app restart or an outage is counted like a quality failure. Healthy slices park, and the breaker trips. With Opus in every seat, one limit kills all agents at once, so three parks in a row is likely. **Fix:** keep two counters in `state.json`, `attempts` (quality) and `restarts` (infra). Parks and the breaker read only `attempts`. On a limit, write the reset time to `state.json`. The tick after the reset resumes from the last pushed sha.

11. **The coordinator's own context fills, and it drifts.** Every finished agent's reply lands in the coordinator's context. "Required fields, no caps" invites long replies. After 20 or so slices it compacts, loses rules, and repeats last run's drift: skipped lanes, its own reviews, a growing plan. **Fix:** agents write their full report to a file. Their reply to the coordinator is the required fields plus the file path and nothing else. That is a channel rule, not a cap on the work. Each wake, the coordinator reads `state.json` and a one-page rules card again. It hands over to a fresh session (state is on disk) after a set number of wakes, or when it notices it has compacted.

12. **Two builders touch the same file.** File lists overlap, or a builder goes outside its list "with a reason". Both slices are green. The second one hits a conflict at landing, which means a fix builder, a fresh review, and maybe a new conflict with the next landing. `uv.lock`, `pyproject.toml`, `conftest.py`, `__init__.py` and registries are the usual collisions. **Fix:** the dispatch script refuses to start a slice whose file list intersects a held slice's list, and treats the overlap as an implied dependency. At READY, it compares the files actually changed with every in-flight slice. The landing script regenerates `uv.lock` after a rebase and never hand-merges it.

13. **Reviewer and builder never converge.** Round 1 raises X. The fixer disagrees, or fixes X differently. The round-2 reviewer is fresh and finds Y and Z in code that round 1 passed. The goalposts move each round, and fresh reviewers make that likely. **Fix:** the round-2 reviewer gets round 1's review and judges only two things: were those blockers fixed, and does the fix diff add a new blocker or touch a fixed line. The fixer writes `DISPUTE <blocker> <reason>` instead of a silent workaround. A dispute still open after round 2 parks the slice, with both views in the report. No third round.

14. **A test fails only under load, or two checks share a resource.** Three builders, slice checks and a landing suite run together on 12 threads. Timing tests fail. Two runs use the same temp folder, port, SQLite file or `D:/Temp/...-ci` path. The old rule, "rerun alone once", turns a real race the slice introduced into a pass. **Fix:** every check run gets its own `TMP`, data folder and free ports. Pytest workers come from a machine-wide slot file, so load stays known. That is a machine budget, not an agent cap. A test that passes alone is recorded in `flaky.tsv`. It may pass the gate only if it also fails under load at the parent. If the slice touched that test's module, it is a blocker.

15. **A restart kills every agent, and the next one doubles up.** The desktop app updates, crashes or is closed, and all background agents die with it. `state.json` still says "held". After recovery, a fresh builder starts on the same branch and worktree, which still hold the dead builder's uncommitted half-work. It commits that work, or its push is rejected and it "fixes" this with a pull, a merge or a reset. **Fix:** on any coordinator start, mark every held seat dead. Before a fresh agent starts, the script saves any uncommitted changes as `evidence/<id>/<attempt>/leftover.patch` and resets the worktree to the last pushed sha. Each attempt gets its own holder id in `state.json`.

16. **The laptop sleeps, or Windows Update reboots it.** Lid sleep or modern standby pauses the app, drops the network mid-push and skips ticks. An update restart at 03:00 kills everything without warning, and the power watcher never sees it. **Fix:** a preflight checklist he runs, or that the script prints, once per run: keep the laptop awake through the app's keep-awake request or the plan's settings, no pending reboot (`Get-PendingReboot`-style check), and updates paused for the night. Each change goes in `ARMED.md` with its undo. After any reboot, recovery runs from item 15.

17. **Windows git traps.** Paths inside `.venv` pass 260 characters, so a checkout half-fails with "Filename too long" and tests break on missing files. A running `python.exe` or Defender scan locks files, so `git worktree remove` fails. Retried with `--force`, it can delete unpushed work. CRLF settings turn small diffs into whole-file diffs, which breaks size checks and reviews. A case-only rename works on Linux and not on Windows. **Fix:** preflight checks `core.longpaths=true`, the LongPathsEnabled value, and a `.gitattributes` with `eol` rules. Cleanup kills processes whose path is in the worktree, removes the worktree only after `ls-remote` equality, and never uses `--force`. A failure goes to `leftovers.md` and is not retried in a loop. The slice checks include `git diff --check` and a case-collision check.

18. **A parked dependency empties the night quietly.** Slice 4 parks at 23:30, and slices 5 to 12 all need it. Seats sit idle from midnight, and the report says "3 landed". Or a dependency is missing from `SLICES.md`, so a builder rebuilds the missing piece itself and duplicates it. **Fix:** when a slice parks, the script marks every slice that depends on it, directly or indirectly, `blocked-by <id>`. These don't count toward the breaker. The report gives the time the run had nothing left to start and names the slice that caused it. The dispatch-time fact check (item 6) catches the undeclared dependency.

19. **Skills that spawn helpers fail inside background agents.** The draft says builders run as top-level sessions "so skills that need helper agents work". Under the new decision they are background agents, and the depth-1 rule stops them spawning. `code-review`, `blast-radius` step 6 and the `show-me-your-work` cross-check then fail or silently do less. **Fix:** name only the rewritten one-agent versions of those skills in every brief, and grep each brief for spawning skills before arming.

20. **Mutation testing eats the night.** Mutating changed lines and running the touched packages' tests for each mutant can take hours a slice on this laptop. **Fix:** run only the slice's new tests against its changed lines, with a time limit per mutant. A survivor blocks only on money, exit or kill-switch lines. Elsewhere it is a low.

21. **Liveness kills a healthy builder.** "Silent for 45 minutes" can't be seen for a background agent, and a builder running a slow but legal test looks silent. **Fix:** liveness means a new push, or a heartbeat file touched by the test wrapper (item 8). Silence means neither has changed in 45 minutes.

22. **Tests reach real credentials.** Agents run tests on the laptop where `qmx/*` broker keys sit in Windows Credential Manager. A test or fixture that calls the real keyring reads them. **Fix:** the test wrapper sets the keyring backend to a fake and points the data folders at the run's temp folder. The money scan greps the diff for keyring calls outside the one allowed module.

23. **The nightly whole-repo run goes red with no suspect.** Several slices landed since the last green run. The breaker stops the run, and nobody knows which slice caused it. **Fix:** on a nightly red, the script runs `git bisect run` over the landed slices with only the failing tests. It names the first bad slice in the report and parks that slice's dependents.

## Rubric for one slice

Score each line pass or fail, from files and logs, never from what the agent says.

1. **Right thing.** Each done-line box has evidence at the final head. The brief's facts held at dispatch.
2. **Real tests.** Each new test fails at the parent for the stated reason, not an ImportError, and passes at the head. Its assertion is a literal value a user would see. No fake is kinder than the real neighbour.
3. **Callers covered.** `how.md` lists every caller of each changed symbol (check it with a grep), and every moved value was searched for in the tests.
4. **Scope.** Changed files match the brief, or each extra file has a reason. The size is in line with the brief.
5. **Fixed lines safe.** Exits, the kill switch, agents' reach to money, and keys: the safety fact was rerun by the reviewer at the head, with matching output.
6. **Checks honest.** No FAIL line at the final head. Windows ran, and Linux ran or is marked not run. No test was weakened or skipped to go green.
7. **Landed result.** The full suite on the rebased result shows no red beyond the baseline. The review covered the code that actually landed (same patch-id, or a range-diff review).
8. **Readable.** The PR body follows v2, with the plain-words line, the door call, and `OPEN:` and `DOC:` lines.
9. **Cost.** Fix rounds, restarts, and wall time from dispatch to landing are recorded, and rounds are 2 or fewer.

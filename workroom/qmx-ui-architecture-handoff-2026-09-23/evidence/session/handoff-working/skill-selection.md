# Skill selection for the UI reset handoff

**Scope:** This is a read-only inspection of local skill guidance to help choose a small, staged set. No skill workflow was activated. Local skill files do not become installed skills in Grok; give Grok a self-contained prompt and the evidence packet, and treat the notes below as inspiration unless the user separately installs equivalent skills there.

**Handoff owner clarification:** Grok should use BMAD architecture now when available, consistent with the user's established workflow. Deep-recon methods support that work rather than replacing architecture. The review-stage architecture entry below is an additional use, not a reason to postpone architecture skill use until Codex review. The primary packet's source/skill map is the selected sequence. The root used writing-for-agents to prepare this packet; the inspection itself did not invoke those workflows.

## Recommended sequence

| Stage | Use | Why it fits | Keep the scope narrow |

It asks for a decision-focused question set, current sources, claims tied to URLs and publication dates, contrary evidence, and explicit gaps. | Send the ideation evidence packet and UI/full-app questions. Do not imply Grok has this local skill. Ask Grok to return source-backed findings, alternatives, open decisions, and a proposed architecture with a short rationale. ## Do not add by default

- `research`: useful for a bounded question against primary sources, but redundant with the decision-grade prompt route for this broad cross-app study. Add only if a discrete API/platform fact needs a separately sourced answer.
- `writing-for-agents`: useful if authoring a reusable skill, `AGENTS.md`, or another agent instruction file. It is not a necessary skill in this pipeline; the documentation factory already has agent-first writing rules.
- `verify-ui-change`: keep as a fallback reference if implementation is a small isolated UI change. For this app's larger user-facing reset, use `install-and-verify` as the Reticle entry point and avoid duplicated verification procedures.
- `bmad-ux`: explicitly excluded by the user.
- Figma workflows: not part of this selection. Paidkit and whole-codebase review are also out of scope now.

## Packaging recommendation

Do not copy a broad skill library into Grok. For the Grok session, provide one self-contained research-and-architecture prompt derived from the Deep Recon Draft criteria, plus the evidence packet and the chosen working stack. If Grok cannot use local files, inline the needed context and require links/dates per claim. Keep the local skill tree intact for later stages: the architecture and epic skills have BMAD scripts/configuration and supporting files, while Documentation Factory relies on its stage/reference/script tree. Package only those complete skill directories if a future runtime genuinely supports skills; copying a bare `SKILL.md` would omit needed workflow resources.

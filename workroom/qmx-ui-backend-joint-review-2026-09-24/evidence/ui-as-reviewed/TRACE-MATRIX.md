## Cancel contract (local AD-23)

- Unique host function: `apps/qmx-ui/src/lib/host/dispatchCancel`.
- CT-40 addable command `cancel_job` (absent at `34c148b`, COMP-QMA-WIRE). **Not** seed `stop_run` (agent/mission stop / `agent_stop` hook).
- Fields: `handle_id`, `logical_run_id`, `attempt_id`, `command_id`, `expected_state`.
- Principal/grant: **operator** of the JobHandle’s immutable **`originating_psess`** (written at admit). Observation is **not** cancel authority. Coordinated authority remains `JobHandle.cancel` (parent AD-26). **Not** a new `InvocationEnvelope` invoke. `machine` cannot take this path. `unknown` is not cancellable (`unknown.resolve` only).
- `expected_state`: JobHandle state plus `attempt_id`. A non-terminal advance `queued`→`running` does **not** invalidate the same `command_id`. Already-terminal → recorded no-op. Same-command replay is idempotent.
- Repeat delivery uses the **same** `command_id` (and the same wire `(producer_id, id)` on retry). First durable terminal wins. Cancelled **display** is not proof the worker stopped.
- Callers: `RunInspector.cancel` only through this function. Adapters never import the wire client.

## J-UI-13 — UI/core protocol mismatch (Gherkin-like)

Given a UI client pinned to `expected_qma_api` / `protocolVersion` Vui and a daemon that negotiates Vdaemon or omits a required capability (`caller_kind`, `list_mailbox`, `cancel_job`, or a family the client requires). When the client authenticates and calls `initialize`. Then the handshake returns a typed protocol or capability mismatch; the shell remains usable for surfaces that do not need the missing method; chat, invoke, or cancel that require it refuse rather than hang; and the operator is not sent through pack enable (J-UI-10) or pack rollback (J-UI-12). **Unexecuted.**

## J-UI-14 — Deployed client update / recovery (Gherkin-like)

Given an installed or static-hosted UI client pairing to an already-running daemon. When the operator launches, updates, or recovers **that client** (SPA/static bits, later Tauri webview — not a pack). Then pairing and snapshot restore bring back mailbox and JobHandles without replaying intent; updating client bits does not rewrite daemon sqlite, retarget in-flight pins, or widen grants; a bad client drop rolls back client files only; and this is an installed-product test, distinct from pack install/enable/grant (J-UI-12) and from pack/host enable incompatibility (J-UI-10). **Unexecuted.**

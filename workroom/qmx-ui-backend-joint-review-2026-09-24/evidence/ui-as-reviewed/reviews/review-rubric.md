## What works

Paradigm is a real contract: **differentiated-shell client over pack-and-grant host**, not a sixth COMP, not a second scheduler or grant store, not screen-kit, not Qt, not LSE ML Studio as layout.

- **Inherited table** binds parent AD-1..AD-31 and kit AD-1..AD-9 read-only. Conflict examples (sixth COMP, json-render/MCP as identity, nested grant union, app-use apply, layout on `psess:`, cancel on dispose, replay unacked intent) are named as conflicts. Named parent amendments still bind: envelope `instance_id` required; authoring invoke needs exactly one `selected_refs` kind `instance_id`; `caller_kind` specified and **absent** at `34c148b`.
- **AD-1 / AD-12** keep the host a client of `qma-wire` (CT-40). Rust/Tauri must not become a second orchestrator. Python compute stays in CPython 3.14 processes. Closing a browser never cancels JobHandles.
- **AD-2** uniquely refuses React/Next, Qt, SvelteKit 3 as required, Tauri 3 alpha, paid kits, wrapping every primitive. SPA mode (`ssr = false` + `@sveltejs/adapter-static` + `200.html`) is a real deploy contract. Re-pin lockfile at isolated scaffold is the right deferral for hashes.
- **AD-5 / AD-8 / AD-13 / AD-14** keep presentation, execution, and JobHandle lifetime independent. Widgets bind/paint; only the shell issues InvocationEnvelope. `failure_class=view` is mount/stale/unhealthy. Close ≠ stop ≠ cancel. `unknown` is non-terminal. GAP-0100 consumes listing axes + kit diagnosis; it is not a second fencing machine.
- **AD-6 / AD-15** keep three presentation lanes, native first; catalog `action` = existing `op_id`; MCP HTML cannot grant; **no `ui_view` contribution point this sitting**. Python core must not take `@json-render/*` (kit AD-8).
- **AD-9 / AD-16** refuse LSE as default ML UI, live Board scribble as Mission, lossless code-to-graph, merging live Task Graphs. UI work is a sibling stream from `integration@34c148b`; do not reuse `.worktrees/ui` at `af66288`. Types are not e2e.
- **Deferred table** is mostly the right park: scaffold hashes, Tauri installer/child-kill proof, `ui_view` mint, GAP-0073/0070/0058, brand, envelope crypto, live daemon protocol server, workload numbers, `main` promotion.

#### H-1 — Home, Copilot, and Settings are not one interior-and-invoke contract

**Where:** AD-3 mermaid (`HOME` and `COP` as separate interiors; required interiors list omits Settings and treats Library only via AD-10); AD-3 Rule (“Selecting a destination replaces the interior”); AD-4 Rule (Home/main is `authoring` with `app_instance_id` absent; two tabs of one product share one `psess:`); Inherited table (authoring invoke needs exactly one `selected_refs` kind `instance_id`); kit AD-3 (authoring with absent instance **may not invoke**); companion `EXPERIENCE-AND-LAYOUT.md` (Home **and** Copilot both map to the main-copilot interior; Settings is a rail destination).

**Two conforming units**

- **Unit A — one main-copilot family.** Destinations above the divider are Home, Copilot, Library, Settings. Home and Copilot are the **same interior family** (session/history column, conversation, tabbed preview). Home is that family with `profile=authoring` and `app_instance_id` absent. Copilot is the same family with a selected `psess:`. Settings is first-run/readiness chrome, not a fourth family and not a third profile. Invoke from this seat is `INVALID_INPUT` unless exactly one `selected_refs` kind `instance_id` is present; envelope `instance_id` stays required. Chat, attention, and Library browse without invoke remain allowed.
- **Unit B — three shells.** Reads the AD-3 mermaid literally. Home is an attention/readiness dashboard. Copilot is a separate three-column chat. Settings is a fourth interior. Home composer invokes against “whatever is selected” or a synthetic home instance (parent AD-24 uniqueness domain becomes optional). A third unit treats two browser tabs as two `psess:` rows because “two tabs of one product” is ambiguous with “switching the visible app restores the relevant `psess:`.”

All three obey “no third profile,” “tabs are chrome,” and “layout is not durable.” What diverges: GAP-0081 rail law, whether J-UI-01/SCN-0023 is inspect-only or a real Home invoke path, and whether Settings is in the seed routes as a family or a card stack.

This sitting’s job is chrome. The defect is uniqueness of AD-3/AD-4: the inherited table states the invoke bind; the local Rules do not, and the mermaid contradicts the companion.

**Action:** autofix. One closed clause under AD-3 and AD-4:

1. Rail destinations above the divider: Home, Copilot, Library, Settings. Opened apps below the divider are instances.
2. **Main-copilot family** (required interior 1) is sessions | conversation | tabbed preview. Home **is** that family with `profile=authoring` and `app_instance_id` absent. Copilot is the same family with a selected `psess:`. They are not two layout families.
3. Settings is destination chrome over listing-axis cards (same readiness language as AD-11), not a fourth interior family, not a third `ProductSessionProfile`.
4. Mini-app and Authoring/ML remain required interiors 2 and 3. Library is AD-10 (platform destination over typed hits).
5. Authoring/Home invoke is forbidden until exactly one `selected_refs` kind `instance_id` is present (kit AD-3). Envelope `instance_id` remains required (parent AD-24). Zero or many such refs → `INVALID_INPUT`. Attention, browse, and chat without invoke stay allowed.
6. “Two tabs of one product share one `psess:`” means two **chrome** tabs (work-area or OS windows) of the **same** `psess:` / instance. Switching the visible **app** restores that app’s `psess:`; it does not merge transcripts or union grants.

#### H-3 — v1 runtime envelope this sitting owns is not unique: client families, SPA origin, daemon data root

**Where:** scope (“integration with qma-wire/qma-daemon, desktop/local/remote operation”); AD-2 (static SPA); AD-11 (probe `127.0.0.1:8765`; start-local or connect-remote); AD-12 (host-supervised daemon; Tauri later); AD-16 (“live JSON-RPC/HTTP/event server is a **backend add** the UI depends on, not a UI-owned bus”); sequence diagram (command JSON-RPC, then query snapshot); parent CT-40 families @ 34c148b (`jsonrpc_websocket` / `http_get` / `durable_stream` in `families.py`; `DaemonProcess._handle_client` discards bytes; default `QMA_DAEMON_ROOT` is cwd-relative `"qma-daemon-data"`); research 10 and 14 (proposals, not spine law); assignment 03-EXPERIENCE-SCOPE §6 (data directories, process supervision, who serves the UI).

**Two conforming units (transport)**

- **Unit A — three families.** UI client speaks CT-40: commands JSON-RPC 2.0 WebSocket; queries HTTP GET snapshots (authoritative); events `wire.attach` durable stream (not authoritative). No UI BFF. No REST invoke API.
- **Unit B — collapsed bus.** Everything over one fetch/SSE, or one JSON-RPC socket that also serves the SPA, or a new middleware. AD-16 “not a UI-owned bus” still “holds” as a slogan.

**Two conforming units (origin / data root)**

- **Unit A — static client + stable daemon root.** SPA is `adapter-static` + `200.html`, loaded from a static origin or later Tauri webview — **not** a new protocol on listener `8765`. Host-supervised daemon sets `QMA_DAEMON_ROOT` to a stable per-user directory. Loopback may use `ws://` + `http://`. Non-loopback requires `wss://` + HTTPS queries + operator-recorded config.
- **Unit B — daemon-origin / cwd root.** UI is served from the wire port. Two launches from different folders create two sqlite trees (inspect default). Remote connect is mixed with local retarget (AD-11 Prevents named this; origin silence still allows it).

This sitting owns desktop/local/remote. Deferred correctly parks the **live server** as a backend add and the **Tauri installer** as later. It does not park how the UI client talks, where the SPA comes from, or where a host-spawned daemon writes.

**Action:** autofix. One closed clause under AD-2, AD-11, AD-12 (and restated in the sequence diagram):

1. UI client **is** a CT-40 client: command = JSON-RPC 2.0 WebSocket; query = HTTP GET snapshot (authoritative); event = durable stream via `wire.attach(scope, since_seq)` (progress not truth). Reconnect is that query (`producer_id` stable + `since_seq` / product-session cursor). No UI BFF. No REST invoke. No fourth store.
2. Static SPA origin is file/static-host or later Tauri webview. Listener `127.0.0.1:8765` remains initialize + the three families. Do not serve chrome as a new bus on that port.
3. Host-supervised local daemon sets `QMA_DAEMON_ROOT` to `%LOCALAPPDATA%\QMX\qma-daemon` (Windows) or `$XDG_STATE_HOME/qmx/qma-daemon` (Linux). Document the env. Do not ship the cwd-relative inspect default as the product.
4. Non-loopback: `wss://` + HTTPS queries + explicit recorded operator config; unauthenticated bind is a hard refusal (inherit `listener.py`). Never silently retarget remote failure onto local (already AD-11).
5. v1 supported mixes (AD-5): browser + local daemon + native pane; headless + qmb CLI/wire; browser + recorded remote. Unsupported in v1 (typed reason): computer-use (GAP-0070), Tauri-required continuity, daemon-as-SPA-server, GAP-0058 single-machine node.

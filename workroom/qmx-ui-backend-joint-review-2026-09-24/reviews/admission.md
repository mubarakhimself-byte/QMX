# Joint UI/backend review — admission, host, and provider bootstrap

**Verdict: return for bounded architecture amendment before Documentation Factory.** The earlier R2 defect is closed: the live UI and backend candidates consistently require fresh QMB confirmation of that pending request or renewal with an existing valid proof; remembered Origin alone cannot issue a session (`backend/ARCHITECTURE-SPINE.md:94-104`; `backend/PAIRING-AND-ADMISSION.md:16-34`; `ui/BOOTSTRAP-AND-AUTH.md:32-40,168-181,226-232`). Browser storage is also consistently tab-scoped, and the named parent amendments are valid inputs rather than failures merely because implementation is absent.

The packet is not yet a single implementable operator-trust and provider-bootstrap architecture. The following are contract gaps, not findings that candidate code is missing.

Anchor aliases: `backend/` = `workroom/qmx-ui-backend-joint-review-2026-09-24/evidence/backend-as-reviewed/`; `ui/` = the sibling `evidence/ui-as-reviewed/`. Code anchors are under `.worktrees/integration-inspect/` at the reviewed SHA.

## Findings

### 1. The bearer proof is explicitly allowed onto durable and diagnostic surfaces

`pairing_session_id` is the credential that authorizes HTTP and WebSocket access, but the backend calls session ids “not secrets,” makes the raw id the journal-projection join key, and permits traces to name it (`backend/ARCHITECTURE-SPINE.md:100-110,178-187`; `backend/PAIRING-AND-ADMISSION.md:67-79,100-106`; `backend/PARENT-AMENDMENT-MAP.md:28`). The UI repeats that the id is not a secret (`ui/BOOTSTRAP-AND-AUTH.md:185`). Avoiding JSON keys named `token` or `bearer` does not change bearer semantics: possession of the value authorizes the caller.

This also defeats the inherited surface guard rather than extending it. Current `qma-wire` rejects keys such as `token` and `bearer`, but recursively accepts an arbitrary `pairing_session_id` field (`.worktrees/integration-inspect/qmx-agents/packages/qma-wire/src/qma/wire/auth.py:35-47,119-175`). A journal or trace disclosure can therefore confer operator access until expiry or revoke; the WebSocket subprotocol and Authorization header can also be captured by ordinary request logging.

**Required bind:** classify the raw pairing proof as credential material. Generate a high-entropy, WebSocket-token-safe value; return it only to the browser; persist a verifier/hash plus a nonsecret record id and lifecycle metadata, not the raw bearer, in the forever journal/projection. Redact Authorization and the `qmx.pair.*` offered subprotocol from access logs, traces, diagnostics, crash reports, and status. Extend the surface rule by semantic field/value class rather than relying on a forbidden-key spelling list. Apply the same custody decision to any one-time confirmation claim value.

### 2. The first operator identity is circular and conflicts with the declared allowlist

The confirmation path requires `qmb host pair <code>` to enter the existing authenticated wire as an operator and copy an existing operator `CredentialRef`; pairing may not mint that ref (`backend/ARCHITECTURE-SPINE.md:100-116`; `backend/HOST-LIFECYCLE.md:14-20`). On a clean root, however, the packet never defines how that first operator transport identity is provisioned, selected, or verified. The candidate additionally requires the copied value to be an “allowlisted operator login ref,” while its only declared broker allowlist contains provider/compute/corpus/telemetry families and no operator-login family (`backend/ARCHITECTURE-SPINE.md:104,148-152`; `backend/PROVIDER-AND-COMPAT.md:10-20`; `.worktrees/integration-inspect/qmx-agents/packages/qma-core/src/qma/core/barriers/credential_allowlist.py:41-60`). Current `authenticate_before_protocol` is only a reference/principal shape gate; it does not resolve a credential or prove that the caller is the operator (`ui/BOOTSTRAP-AND-AUTH.md:141-154`; `.worktrees/integration-inspect/qmx-agents/packages/qma-wire/src/qma/wire/auth.py:92-116`).

The required `registry:pairing.session_ttl` holding rule compounds the cycle: pairing refuses while it is unset, but registry writes are inherited operator-only actions. A clean installation has no defined authenticated action that can set the prerequisite and then confirm the first browser.

**Required bind:** choose one initial trust root and its recovery path. For example, define a QMB-local OS-user control channel that establishes a durable operator principal and may set the pairing TTL, then have browser sessions map to that principal; or define a separately provisioned operator transport credential family, its exact provisioning command/store, and validation path. Name the amendment if it changes QMA AD-24. Do not reuse a provider ref as a dummy operator identity. The result must describe clean root → start → establish operator → set/obtain TTL → confirm pending → browser session without assuming an already-authenticated wire.

### 3. Confirmation, renewal, expiry, and revocation do not form one closed lifecycle

The legal issuance paths are clear, but their state transitions are not. A confirmed pending row has no consume/claim state, so repeated `/pair/confirm` calls can be read as minting multiple new ids; there is no lost-response idempotency rule (`backend/PAIRING-AND-ADMISSION.md:40-58,63-77`). Renewal deliberately leaves both ids live, but the new row's `expires_at` is not defined as inheriting the lineage's absolute expiry or receiving a fresh TTL (`:67-77,100-106`). Rolling expiry would let any still-valid bearer extend itself indefinitely; inherited expiry gives materially different UX.

Expiry enforcement also forks. The UI says expired/revoked sessions drop queries and WebSockets (`ui/BOOTSTRAP-AND-AUTH.md:311-318`), while the backend explicitly closes sockets on revoke but does not say an already-authenticated socket closes when its TTL elapses (`backend/ARCHITECTURE-SPINE.md:100-104`; `backend/PAIRING-AND-ADMISSION.md:77-79,102-106`). Finally, `--origin` does not define whether it invalidates every live id and every confirmed-but-unclaimed pending row, or how it orders against a concurrent renew (`backend/HOST-LIFECYCLE.md:19-20`).

**Required bind:** publish a small transition table covering pending creation, confirmation claim, confirm retry/lost response, renew retry, lineage expiry, session revoke, origin revoke, and daemon restart. Make confirmation consume-once with an idempotent recovery result; decide absolute versus rolling renewal lifetime; close or re-auth active sockets at expiry; and make origin revoke a journal-ordered cutoff that invalidates all earlier sessions and unclaimed confirmations for that origin. Include the renew/revoke race outcome.

### 4. A clean machine can reach the shell, but cannot bootstrap a provider

The provider companion allows the browser to select an already-stored reference and defers every OS-store write to a later QMB/native helper (`backend/PROVIDER-AND-COMPAT.md:10-24`). The WinCred reader is itself only an adoption gap. Yet the installed-product table says a clean machine needs no checkout and lists start → pair → initialize without stating that provider use requires external pre-provisioning (`backend/PROVIDER-AND-COMPAT.md:36-47`). The UI's first-run card is retry-only (`ui/COMPONENT-CONTRACTS.md:35-43`) and its first-run rule promises partial readiness without a credential acquisition path (`ui/ARCHITECTURE-SPINE.md:159-169`). Current code confirms the asymmetry: the production Windows backend exposes exact read only and reports that its reader is unwired; only the test memory backend has `put` (`.worktrees/integration-inspect/qmx-agents/packages/qma-daemon/src/qma/daemon/proxy/broker.py:65-108`).

**Required bind:** either include one v1 QMB/native write-once flow with allowed ref grammar, OS-store owner, overwrite/refusal behavior, and the returned nonsecret ref, or explicitly scope “clean machine” to shell-only and make external credential provisioning a documented prerequisite. Then bind the ReadinessCard states for absent ref, unresolved ref, provider unhealthy, and usable provider. The page must continue to receive refs and health only, never secret values.

## Admission result

The origin-only R2 correction, same-tab reload versus cold start, QMB ownership, exact-origin checks, and provider-secret separation are suitable foundations. The host lifecycle is sufficiently placed at this altitude: QMB owns `start|status|stop`, the stable per-user root and sole-writer lock are named, browser close is detach rather than stop, and local stop never targets remote (`backend/HOST-LIFECYCLE.md:10-20,31-54`). Signal/control-channel choice, graceful-stop timeout, and stale-lock mechanics may be closed in implementation stories so long as those invariants and daemon-owned lock release hold.

Documentation Factory should wait for the four bounded contracts above, especially bearer custody and the first-operator trust root. No application implementation or runtime proof is required to close them; explicit parent amendments are acceptable where the chosen trust root changes inherited QMA transport custody.

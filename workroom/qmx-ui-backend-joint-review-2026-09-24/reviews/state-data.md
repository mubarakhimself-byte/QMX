# Joint UI/backend review — state, durable identity, cancel, and artifact transfer

**Verdict: return for a bounded architecture amendment before Documentation Factory.** Mailbox recovery is substantially closed: the frozen candidates agree on pre-ack `(producer_id, wire_id)`, journal-lifetime collision handling for `send_message`, authoritative snapshots, no intent replay, and `product_session_id` inheritance. Cancel also converges on `handle_id == job_id`, an immutable originating product session for UI-started work, principal equality, same-command replay across `queued -> running`, and first-terminal-wins. Missing code at `34c148be` is planned/adoption work and is not a finding.

The remaining gate is the artifact-transfer data plane. It cannot yet prove that the authorized destination received and durably verified the bytes. Two smaller authority/identity seams should be closed in the same amendment.

## Findings

### 1. Artifact transfer has no closed route from the source daemon to one authorized destination and no completion authority

The UI stages bytes on the authenticated local daemon, then asks for explicit transfer when execution placement is elsewhere (`ui/LIBRARY-AND-ATTACHMENTS.md:84-122,254-261`). The backend creates `artifact_transfer_ticket {ticket_id, fp1, destination_placement}` and requires the destination to pull `GET /artifacts/<fp1>` as any `machine` principal presenting that ticket (`backend/ARCHITECTURE-SPINE.md:130-134,166-170`; `backend/ARTIFACTS-AND-TRANSFER.md:31-42`). The host contract simultaneously says v1 is local-workstation-first and a recorded remote is a different HTTPS/WSS daemon origin (`backend/HOST-LIFECYCLE.md:50-54`). The inherited QMA topology has no relay or tunnel: a remote worker may dial its daemon, while the daemon defaults to loopback and is reachable remotely only after an explicit TLS non-loopback configuration (`.worktrees/integration-inspect/_bmad-output/planning-artifacts/architecture/architecture-QMA-2026-08-28/ARCHITECTURE-SPINE.md:108-112`).

This leaves two independently compliant but incompatible placements. A remote worker already attached to the source daemon can pull only if that daemon has a recorded reachable HTTPS origin; an instance owned by a different remote daemon cannot reach the workstation's default `127.0.0.1:8765`. Nothing in the ticket distinguishes those topologies or binds the source endpoint to the destination environment's network allowlist.

Authorization and completion are also open. The ticket is bound to a placement string, but the GET checks only `principal_class=machine`, a Story 41.4 credential, and the ticket id. It does not bind the credential or authenticated wire session to the resolved destination environment/instance. The command does not say how that destination receives the ticket. Finishing the GET proves only that the source wrote response bytes; the destination's later hash check and durable possession have no named acknowledgement back to the ticket projection. There is no transfer result query or product-session `command_id`, so a lost command acknowledgement can create another open ticket after the ordinary wire dedup window. The UI nevertheless treats successful transfer as the point at which invoke may cite the fp1, and says interrupted transfer leaves no runnable destination object (`ui/LIBRARY-AND-ATTACHMENTS.md:107-120,283-288`).

**Required bind:** define one ticket lifecycle and one legal topology. At issuance, resolve and persist the source daemon origin, fp1 plus byte count, requesting operator/product session, destination environment or daemon identity and revision, and the exact machine credential audience allowed to redeem it. Refuse issuance with a typed unreachable result unless that destination can reach the recorded source HTTPS origin under its inherited network allowlist; default loopback is not a remote route. Deliver the ticket over the already-authenticated destination control connection, require that bound machine to pull, and require a destination-authored acknowledgement after hash/byte-count verification and durable placement. Only that acknowledgement closes the ticket and permits invoke on the destination. Bind retries/lost acknowledgements to a durable `command_id` or an equivalent recoverable ticket identity; define expiry/revoke and interrupted-pull states. A different-daemon copy may be chosen instead, but it needs the same destination binding and completion proof rather than treating any machine credential plus ticket id as authority.

### 2. The mailbox query is session-authorized, but initial `send_message` admission can still be implemented as operator-only

The UI sends a client-chosen `product_session_id` in the ordinary `send_message` payload, and the daemon copies it onto the durable Envelope (`ui/CHAT-AND-HISTORY.md:35-43,53-67`). The backend companion explicitly applies `connection principal == product_session.principal` to `list_mailbox` (`backend/MAILBOX-AND-DELIVERY.md:32-45`). Its dependency map describes `send_message` authorization only as an operator connection, while the adjacent query row names “operator of that `psess:` (same principal)” (`backend/DEPENDENCY-MAP.md:58-65`). Spine AD-7 contains the equality sentence after the query definition (`backend/ARCHITECTURE-SPINE.md:118-122`), so one builder can reasonably apply it to both operations and another only to the query.

The second reading lets paired operator A append a root message carrying operator B's `product_session_id`; B can later read it even though A cannot query B's mailbox. Reply inheritance and retarget refusal do not protect the first root write.

**Required bind:** state that `send_message` admission resolves the supplied product session and requires the authenticated operator identity to equal its durable principal before the Envelope or dedup record is appended. Daemon-originated replies/questions may acquire the session only by inheriting an authorized causal parent; they may not accept an arbitrary retarget. Keep the existing query equality rule.

### 3. The cancel tuple is named but its stale-attempt fence and headless null case are not closed

`cancel_job` carries `handle_id`, `logical_run_id`, `attempt_id`, `command_id`, and `expected_state`; the durable handle carries the corresponding run/attempt identity (`backend/CANCEL-AND-HANDLES.md:12-35`; `backend/ARCHITECTURE-SPINE.md:124-128`). The packet defines the special `queued -> running` case and excludes `expected_state` from the idempotency hash, but never says that `logical_run_id` and `attempt_id` must equal the durable handle before cancel. A builder may treat them as diagnostics while another uses them as fences. That makes a stale retry capable of cancelling a different attempt wherever a handle identity is reused or restored incorrectly.

The record amendment also reads as if every JobHandle must contain `originating_psess`, while the inherited envelope permits absent caller/callee product-session refs and the reviewed UI retains headless QMB invocation (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:228-233`; `ui/TRACE-MATRIX.md:51-52`). A headless job therefore has no honest value to write. Nested agent-started children have the same boundary unless their invocation actually carries a product session.

**Required bind:** make `originating_psess` explicitly optional on non-product-session admissions and make UI `cancel_job` unavailable when it is absent; keep the separate authenticated QMB production door. For the UI path, derive the product-session `command_id` namespace from the handle's stored origin, require exact `handle_id/job_id`, `logical_run_id`, and `attempt_id` equality, and define `expected_state` as a non-authoritative observation whose `queued/running` change does not alter the canonical dedup payload. Terminal remains an idempotent recorded no-op and `unknown` remains non-cancellable.

### 4. The two new durable cross-store fields need an explicit exception to the inherited reference-name law

AM-02 puts `product_session_id` on a mailbox Envelope, where it references a row owned by the product-session projection. AM-04 puts `originating_psess` on a JobHandle, with the same cross-store meaning (`backend/PARENT-AMENDMENT-MAP.md:18-22`). Inherited QMA conventions require cross-store pointers to use `_ref` and enumerate exactly ten exceptions; neither new name is one of them (`.worktrees/integration-inspect/_bmad-output/planning-artifacts/architecture/architecture-QMA-2026-08-28/ARCHITECTURE-SPINE.md:346-352`). The current CT-48 parser likewise treats its unsuffixed exceptions as an explicit closed set (`.worktrees/integration-inspect/qmx-agents/packages/qma-core/src/qma/core/ports/mailbox.py:98-115,424-431`).

This is not a stylistic naming request: a builder applying the parent validator can reject the amended records, while a builder following AM-02/AM-04 accepts them.

**Required bind:** either rename the durable pointers to reference-law-compliant names and update both packets, or add these exact legacy field names as explicit parent/QMA convention amendments with one canonical meaning. Do not leave the field amendments and the closed exception list simultaneously normative.

## Gate disposition

Resolve finding 1 before Documentation Factory; it is the load-bearing blocker for J-UI-09 and remote execution placement. Resolve findings 2-4 in the same bounded architecture amendment so mailbox writes, cancel replay, and durable record validation have one authority model. No implementation, epic rewrite, or renewed UI styling/navigation work is needed.

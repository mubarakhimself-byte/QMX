# Codex adversarial seam review

## Verdict

**Return for amendment before the UI candidate becomes a build substrate.** The candidate preserves the parent laws around COMPs, grants, envelopes, JobHandles, pack lifecycle, typed hits, and client-only chrome. The remaining failures are concentrated at six UI-owned seams. Two teams can follow the candidate and still disagree on who boots and authenticates a browser session, whether a chat send is a mailbox command or an operation invoke, which authority an embedded renderer inherits, what identity a runnable draft has, and how cancel and multi-tab command identity cross the wire.

The frozen 85 `P1-*` / `P2-*` items and `SCN-*` inventory were treated as specifications only. `JOURNEYS.md:10-14` explicitly labels them specification/on-disk status, and this review found no evidence that they are passed browser, process, or installed-product tests. The deterministic spine lint is clean; that is not evidence that these semantic seams interoperate.

## Findings

### Critical — Browser-first v1 has no process owner or pre-protocol authentication bridge

**Evidence.** Local AD-11 requires the UI to probe `127.0.0.1:8765` and offer **Start local daemon** (`ARCHITECTURE-SPINE.md:155-159`). Local AD-12 then declares v1 to be a **browser client + host-supervised local daemon**, while deferring Tauri and its installer/process work (`ARCHITECTURE-SPINE.md:161-165`, `279-294`). AD-2 says the SPA comes from a static origin and never from daemon port 8765 (`ARCHITECTURE-SPINE.md:101-105`). The current process only binds TCP and discards every byte (`.worktrees/integration-inspect/qmx-agents/packages/qma-daemon/src/qma/daemon/process.py:358-401`, `418-432`). Parent CT-40 requires authentication with a Credential-Broker-resolved reference **before protocol bytes** and an `operator` or `machine` principal (`.worktrees/integration-inspect/qmx-agents/packages/qma-wire/src/qma/wire/auth.py:1-7`, `92-116`). The candidate's own Tauri research says a normal browser does not get native process/filesystem/credential capabilities and explicitly leaves browser Credential-Broker authentication unproved (`research/17-workflow-tauri-python-sidecar.md:27-30`, `70-73`). First-run research also proposes an OS Credential Manager write helper even though browser v1 has no native helper (`research/14-firstrun-packaging-placement.md:95-114`).

**Two conforming builds.** Team A ships a Python launcher which sets `QMA_DAEMON_ROOT`, starts `python -m qma.daemon`, provisions or selects the operator credential reference, starts a static server, and opens the browser. Team B installs a persistent per-user service/tray process which owns the daemon and credential bridge; the SPA merely attaches. Both can reasonably claim “browser client + host-supervised daemon,” no sixth COMP, and no Tauri. They disagree on process lifetime, update/rollback unit, port ownership, credential handoff, **Stop local runtime**, and whether closing the launcher ends local work. A third team can read “browser v1” literally and make Start local a help screen because browser JavaScript cannot spawn Python.

**Consequence.** The first-run journey cannot be implemented independently from the packaging story, and a UI can either fail before `initialize`, weaken parent pre-protocol auth, or create an unreviewed native launcher that owns daemon lifetime and secrets. The candidate labels installer/process ownership Deferred even though v1 startup depends on it.

**Required fix.** Name one v1 bootstrap owner and protocol. It may be a small native/Python launcher, a user service, or a required externally started daemon, but the spine must choose. Bind: static-origin serving, stable data root, single-instance/port arbitration, start/health/stop semantics, clean shutdown versus durable remote work, how the browser obtains a non-secret operator `credential_ref`, how that reference is validated before CT-40 bytes, and allowed browser origins/CORS. If no native/bootstrap process ships in v1, remove **Start local daemon** and **host-supervised** from browser v1 and make an externally running daemon an explicit prerequisite.

### Critical — Home chat and operation invoke are conflated, and no durable conversation owner is named

**Evidence.** AD-4 allows Home/authoring to browse, receive attention, and **chat without invoke** while it has no `instance_id`; any invoke requires exactly one selected `instance_id` and an envelope instance (`ARCHITECTURE-SPINE.md:113-117`). AD-8 says composer submit calls the unique `dispatchInvoke`, which always builds `InvocationEnvelope` (`ARCHITECTURE-SPINE.md:137-141`). The sequence diagram also routes “press widget **or send message**” through `dispatchInvoke` and an envelope (`ARCHITECTURE-SPINE.md:244-260`). Yet `COMPONENT-CONTRACTS.md` separates `ConversationPane.send` from `Composer.submit` (`COMPONENT-CONTRACTS.md:32-37`), and the researched parent path leaves a real fork: `send_message` mailbox command **or** granted operation invoke (`research/10-transport-reconnect-ops.md:290-298`). Parent AD-24 requires `instance_id` on every public operation envelope (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:228-232`).

The persistence side is also incomplete. The candidate says app switching restores the relevant history (`ARCHITECTURE-SPINE.md:113-117`; `EXPERIENCE-AND-LAYOUT.md:42-51`), and `ConversationPane` consumes “session events + snapshot” (`COMPONENT-CONTRACTS.md:33-35`). But parent `product_session` durable fields contain context/grants/refs, not messages or a conversation id (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:130-134`), and the inspected projection confirms that exact field set (`.worktrees/integration-inspect/qmx-agents/packages/qma-daemon/src/qma/daemon/sessions/product_session.py:734-782`). A `psess:` maps to many execution `sess:` records; the candidate correctly says a `sess:` is not a third chat, but it never names the record that owns transcript order, questions, edits, or result links.

**Two conforming builds.** Team A treats `ConversationPane.send` as CT-40 `send_message`, keeps `Composer.submit` for operation invocation, and indexes mailbox/message events by `psess:`. Team B models copilot chat as a granted operation, so every message uses `dispatchInvoke`, a GrantRecord, and an instance. Both are supported by different candidate passages. Team B cannot support the promised Home chat without inventing a synthetic instance; Team A cannot implement history restore unless it invents a durable conversation projection or a specified mailbox-to-`psess:` query.

**Consequence.** Independently built shell and backend stories will disagree on the wire method, required authority, idempotency key, streaming event scope, and storage/query owner for the same Send button. Reconnect can restore grants and selected refs while losing or misrouting the visible conversation.

**Required fix.** Split the contracts explicitly. `ConversationPane.send` must name its CT-40 command, ack/idempotency identity, `psess:` binding, message/question/result event scopes, authoritative history query, and durable owner/retention. `Composer.submit` invokes a granted operation through `dispatchInvoke`. Remove “send message” from the invoke-only sequence unless a specific tool call is being made. State that Home chat needs no `instance_id`; a copilot tool call does and uses the selected instance envelope.

### High — Hosted and generated UI can inherit the whole session grant bag

**Evidence.** AD-6 requires MCP App `tools/call` to be intercepted “against the session GrantRecord,” and json-render actions to name an existing `op_id` (`ARCHITECTURE-SPINE.md:125-129`). AD-8 funnels MCP, json-render, native widgets, graph Run, composer, and command palette through the same `dispatchInvoke` (`ARCHITECTURE-SPINE.md:137-141`). AD-15 allows coding agents to author constrained catalog specs while navigation/widgets remain request blobs (`ARCHITECTURE-SPINE.md:179-183`). Parent GrantRecords are narrower than a session: they bind audience, contribution tuple, instance, config revision, op/version, effect, parameter ceiling, and optional account scope (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:228-232`).

**Two conforming builds.** Adapter A gives each iframe/catalog an immutable host context `{psess, view_id, contribution, instance_id, allowed op_ids}` and derives grant/envelope fields itself. Adapter B accepts any `tools/call` whose `op_id` has some valid GrantRecord in the current `psess:`; the host still “intercepts every call against the session GrantRecord,” and `dispatchInvoke` still performs backend comparison. Both obey the written rule. B lets an app-use iframe exercise another contribution's granted operation, or retarget an action to another granted instance, whenever those grants coexist in the session.

**Consequence.** The renderer becomes an authority selector even though the spine says presentation is not authority. Native widgets, json-render, and MCP Apps then have different effective isolation despite sharing a host dispatcher.

**Required fix.** Bind each mounted adapter to an immutable, host-minted context. Frames/specs may supply only schema-valid operation input and a declared action/tool name. The host derives `psess`, contribution, instance/config revision, grant id, account/placement ceiling, caller kind, and snapshot cursor; it ignores or refuses those fields from untrusted content. Intersect the mounted view's declared action set with the exact matching GrantRecord and current health. Specify iframe origin/sandbox/message validation and dispose/revocation behavior. Use the same rule for json-render ActionProvider and native `WidgetFrame` so a catalog is never a second grant list.

### High — Draft, published template version, installed pack version, and runnable pin can still collapse

**Evidence.** AD-8 requires expand/return to retain “draft/version” (`ARCHITECTURE-SPINE.md:137-141`). AD-9 says code/detail is for an identified draft or published version, validation and test-run name that version, running an older version remains distinguishable from editing a new one, and Graph Run invokes the already-registered template's `start` op (`ARCHITECTURE-SPINE.md:143-147`). `EXPERIENCE-AND-LAYOUT.md:72-86` and `JOURNEYS.md:26-29` repeat the draft/run transition. The parent contract is stricter: a Graph Template is an authored, versioned, plugin-contributed DAG; an enabled `(qualified_id, version)` is immutable; changed bytes require a new version or disable (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:106-110`). Pack lifecycle separately distinguishes installed, validated, enabled, pinned, and running bytes (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:192-196`, `264-268`).

**Two conforming builds.** Team A keeps drafts client-local and permits only published/enabled immutable template versions to test-run. Team B persists a draft under a temporary version, validates/registers it, and invokes its `start` op without enabling the containing pack. A third team overwrites a draft label while pinning only `(qualified_id, version)`. All can display a named “draft/version” and claim Graph Run targets an already registered template, but their run identity, install side effects, cleanup, grants, and reproducibility differ.

**Consequence.** The graph editor and daemon cannot agree on what bytes validation or a test run used. “Run V1 while editing V2” is visual copy rather than an enforceable pin, and a reconnect may reopen a mutable draft whose bytes no longer match the JobHandle.

**Required fix.** Define distinct typed references for editor draft/revision, immutable Graph Template `(qualified_id, version)`, pack instance/version, and graph run/JobHandle. State which transitions create each identity and which are legal to validate or run. If draft test-runs are supported, name the daemon-owned staging record, immutable content hash, expiry/cleanup, grant evaluation, and resulting pinned run reference. Otherwise state that run is refused until the draft is published/validated/enabled as a new immutable version. Expand/return must retain these typed refs, not one ambiguous `draft/version` string.

### High — `RunInspector.cancel` has no unique command path

**Evidence.** AD-13 distinguishes close, stop, and cancel and says cancel is `JobHandle.cancel` only (`ARCHITECTURE-SPINE.md:167-171`). `RunInspector` emits `cancel` and policy-gated `retry` (`COMPONENT-CONTRACTS.md:38-43`), but the unique issuer list excludes `RunInspector` (`COMPONENT-CONTRACTS.md:45`; `ARCHITECTURE-SPINE.md:137-141`). Parent operation descriptors also expose lifecycle verbs `start | query-state | cancel | await` (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:100-104`), while research correctly says seed `stop_run` is not widget cancellation and `JobHandle.cancel` is the coordinated authority (`research/10-transport-reconnect-ops.md:290-296`).

**Two conforming builds.** Team A gives `RunInspector` a direct JobHandle wire client and emits a dedicated cancel command. Team B routes cancel through `dispatchInvoke` as the operation descriptor's `cancel` lifecycle verb with a new InvocationEnvelope. Both can call the backend JobHandle service and preserve first-terminal-wins, but they disagree on command family, grant/envelope requirements, correlation/idempotency identity, lost-ack reconciliation, and whether UI cancel is itself a second invoke. A third team will be tempted to map it to seed `stop_run` despite the research warning.

**Consequence.** The UI and daemon can each implement a valid-looking cancellation surface that cannot interoperate, especially during the cancel/complete and lost-ack races called out by J-UI-08.

**Required fix.** Name one host function and one CT-40 method for cancel, with required `{handle_id, logical_run_id/attempt_id, command id, expected state/revision}` and ack/reconcile behavior. State whether it carries a parent InvocationEnvelope or a JobHandle command envelope, which GrantRecord/principal check applies, and that repeated delivery uses the same command identity. Route `RunInspector` only through that host function; forbid `stop_run` and direct adapter wire imports.

### High — The composer promises resource references that the closed typed-ref set cannot carry

**Evidence.** AD-7 correctly preserves the closed parent selected-ref kinds and refuses `local_path` / `upload_bytes`; it then promises that uploads snapshot to artifact `fp1`, existing files use artifact/dataset/run refs, and remote placement stages or refuses (`ARCHITECTURE-SPINE.md:131-135`). The experience contract also says a widget message adds a reference to the copilot (`EXPERIENCE-AND-LAYOUT.md:53-64`). The research ledger is more precise: inspected `selected_refs` are `artifact`, `research_ref`, `contribution`, `template`, `dataset`, `run`, `attempt`, and `node_ids`; `instance_id` is the named kit add (`research/13-library-lifecycle.md:83-94`). A Knowledge reference is **UI-only until a selected-ref kind exists**, and Knowledge is not `artifact` (`research/13-library-lifecycle.md:146-153`). A CT-44 cite returns copied bytes plus an `artifact_ref`, but that copy is explicitly not an `ArtifactHit` (`research/13-library-lifecycle.md:33-35`, `69-72`). The parent only says durable file handoffs use content `fp1`, schema, provenance, and completeness; it does not mint a UI upload method (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:100-104`).

**Two conforming builds.** Team A snapshots every file, Knowledge citation, and widget result into the daemon artifact store, then places the returned fp1 under selected-ref kind `artifact`. Team B keeps live Knowledge `{source_ref, snapshot_ref, locator}` and widget `{view_id, snapshot_cursor, filters}` context in client chrome and tries to pass it as `research_ref`, `run`, or an additive new kind. A preserves the closed kind name but collapses Knowledge/cite-copy semantics and has to invent the byte-ingest command. B preserves source identity but violates the closed selected-ref catalogue. For ordinary uploads, one team can hash in the browser then invent an upload endpoint; another can inline bytes into invoke despite the explicit refusal.

**Consequence.** File/image, Knowledge, and widget-reference stories cannot meet at `Composer` without either adding an unapproved type, losing provenance, or inventing a backend upload/staging path. Remote execution then cannot tell whether it received a durable snapshot, a live locator, or only a client-side hash.

**Required fix.** Keep the parent taxonomy closed unless a named amendment is intended. For each promised composer source, map the exact UI input to an existing typed ref and state what is unsupported. Separately name the owner and operation that ingests bytes, verifies content fp1, records schema/provenance/completeness, resumes or refuses partial transfer, and returns the durable ref; the browser must not treat locally computed fp1 as proof of host possession. For Knowledge, either add a deliberate citation selected-ref contract preserving `{source_ref, snapshot_ref, locator}`/Citation identity, or say it cannot yet be attached. For widget context, require an existing saved artifact/run/dataset ref or keep the action UI-only; do not persist view/filter JSON as a selected ref.

### Medium — Multi-tab producer and command identities are not closed

**Evidence.** AD-4 says two browser/work-area surfaces of the same `psess:` share one server row (`ARCHITECTURE-SPINE.md:113-117`). AD-11 says reconnect uses a stable `producer_id` (`ARCHITECTURE-SPINE.md:155-159`). CT-40 wire dedupe is `(producer_id, id)`, where the id is producer-minted (`.worktrees/integration-inspect/qmx-agents/packages/qma-wire/src/qma/wire/idempotency.py:50-83`, `130-164`), while parent product-session mutation dedupe has a different namespace `(product_session_id, principal, command_id)` and journal-lifetime retention (`_bmad-output/planning-artifacts/architecture/architecture-QMX-2026-09-18/ARCHITECTURE-SPINE.md:258-262`). Initialize accepts a client producer hint or assigns one (`.worktrees/integration-inspect/qmx-agents/packages/qma-wire/src/qma/wire/initialize.py:84-148`, `201-235`).

**Two conforming builds.** Client A stores one producer id for the whole browser profile and allocates ids with a cross-tab localStorage counter. Client B gives each tab a stable producer id and starts its own `command_id` counter. Both satisfy “stable producer_id” and shared `psess:`. B's two tabs can issue the same product-session `command_id` for different payloads and trigger collision/refusal; A can duplicate an id if its cross-tab lock is imperfect. A third client uses random UUIDs and works.

**Consequence.** Independent shell and session-client units can lose a command as a duplicate or turn an ordinary concurrent edit into a payload-hash collision. Reconnect semantics depend on which surface owns the producer id.

**Required fix.** Define producer cardinality and persistence: one producer per browser surface, stable across that surface's reconnects, or one coordinated producer per installation. Separately require globally unique product-session `command_id`s across all surfaces sharing `(psess, principal)` (for example UUIDv7), preserved verbatim for retries and never regenerated on reconnect. Keep wire `id`, product-session `command_id`, invocation `idempotency_key`, and JobHandle cancel identity distinct in the frontend types.

## Closures that hold

- The UI remains a CT-40 client and does not mint a sixth COMP or a UI-owned grant store (`ARCHITECTURE-SPINE.md:95-99`).
- Native/json-render/MCP presentation lanes remain distinct, and none is a contribution identity (`ARCHITECTURE-SPINE.md:125-129`, `179-183`).
- Tabs/layout do not own `psess:` durability or JobHandle lifetime (`ARCHITECTURE-SPINE.md:113-123`).
- Typed hit classes and Library lifecycle do not collapse into a new Library object (`ARCHITECTURE-SPINE.md:149-153`).
- Query/event/command transport families, product-session CAS/resync, JobHandle states, effect-class retry, and first-terminal-wins are already supplied by the parents; this review does not ask the UI spine to redefine them.
- Existing-vs-proposed claims are mostly honest: live JSON-RPC/HTTP/event serving, optional authoring instance, `caller_kind`, health/logging/retry, Svelte UI, and adapters are all labelled add/unresolved rather than implemented (`CHANGE-IMPACT.md:11-39`).

## Gate disposition

Amend the seven seams above in the primary architecture and component contracts, then rerun lint plus the focused parent-consistency/adversarial gate. The browser bootstrap and chat/invoke findings are blocking because the proposed first vertical slice requires both. The hosted-adapter, draft pin, cancel, and resource-reference findings block generated UI, graph/code, run-control, and composer stories. Multi-tab identity may be fixed as a concise convention if the parent command-id law is cited directly.
